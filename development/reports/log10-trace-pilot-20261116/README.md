## 连续记录与版本关系

连续 trace 记录“看了什么、怎么改、测了什么、怎样反馈”。正式性能图只从中提取已测节点，不以正式点数冒充全部优化轮数。

| 实验线 | 模型调用 | 保存的源码修改 | 设备预检源码 | 正式评测 |
| --- | ---: | ---: | ---: | ---: |
| 开发线 | 24 | 126 | 17（5份失败） | 12 |
| 区域实验 | 3 | 10 | 2 | 3（含固定起点复验） |

开发线前10次调用通过原始日志中的字面写入、替换恢复；后14次的恢复输入／输出分别与保存快照吻合。12个正式源码均出现在恢复链中。区域实验的初始输入来自明确保存的冻结源码，其后的两份新候选均可通过保存的修改链恢复。源码重放仅在内存计算内容SHA，不执行日志中的shell、Python或候选代码。

相邻正式点间共有13条经保存修改链核对的连接（开发11条、区域2条）。中间版本没有正式性能时不填0分；5份预检失败仍在详情中保留。开发第3、4、17、24次调用未改变源码，也保留原调用记录。

开发线和区域实验是不同起点的实验，分别展示；没有把0.851055×直接连到0.915250×。同一内容的再次评测属于新评测事件，而不是新的源码内容。

## 信息来源和计时口径

主线关键箭头分别引用冷缓存探针、宿主剖析、启动ABI／后端源码、实际IR。最后一项的修改前IR读取与修改后IR对照分开记录，后验对照不标为先前修改的触发来源。具体出处可在HTML的“关键箭头”中展开。

模拟器放大图同时呈现完整KGS分数、单个case的真机设备任务耗时，以及模拟器单核各自窗口内的等待比例。三者口径分开；模拟器比例不当作整卡关键路径。修订后目标case任务耗时由49.64降至43.32μs，但仍慢于起点39.26μs，完整分数也未超过起点，因此保留原版本。

原采集的退出异常及核数差异等限制保留在模拟器原件与[区域报告](../regions-method-20261110.md)，不因本次画图改写。

模型／工具内部按原始调用编号及日志行号排序，正式评测保留原UTC时间。部分历史调用缺少时间，外层预检／评测用源码锚点接入事件流；该流是可追溯的部分顺序，不声称所有外层动作的精确交错时间已经恢复。未保存在这些原件中的外层分析动作不补造为事件。工具类别由路径等启发式整理，不能代替“模型明确引用该证据”的因果证明。

这些是development下的研究工具和展示材料，本轮没有改变公开HG-KDA runtime或skill接口。

## 重建与核验

在仓库根目录执行：

```powershell
python -m development.tools.traces --presentation development/manifests/traces/log10_/presentation.json --output development/manifests/traces/log10_/index.json --render development/reports/log10-trace-pilot-20261116
python -m unittest development.tests.test_trace_import -v
```

`--render`生成HTML与SVG；安装Playwright且本机有Edge时，追加`--png`可从同一SVG导出1600×900的PNG。278份关联原件／索引文件已核验SHA，15个正式源码均匹配请求实际提交内容及保存结果，单线合同与设置一致。检查结果见[verification.json](../../manifests/traces/log10_/verification.json)。另检查页面切换、历史入口、节点数与实际排版。
