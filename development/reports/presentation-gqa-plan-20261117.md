# 下周汇报：白盒模拟器驱动的多层次优化

## 汇报主线

以昇腾算子优化为例，说明模拟器提供何种额外判断、该判断为什么指向某一修改层，以及改动后的硬件行为和真机性能是否符合预测。成对 profiling 用于发现差距；热点区域与流水分析是方法主体；源码／IR是解释机制和选择修改位置的桥梁。知识库作为辅助，不作为本轮重点。

已有26项交付表说明端到端效果，但不将全部收益归为模拟器。GQA用一条完整优化过程展示方法；没有实际完成的 IR/pass 修改放入路线图，不写成已验证创新。

## 26项历史中的模拟器

已核查记录见 [历史来源与GQA报告](attribution-and-gqa-20261117.md) 及 `development/experiments/attribution-review-20261117/records.json`。

| 算子 | 已有事实 | 结论 |
| --- | --- | --- |
| selu_ | 修改前分析读取模拟器指令，结合调用间隔选择启动缓存；后续未变快 | 有模拟器辅助参与的历史尝试，非交付净收益证据 |
| upsample_bilinear2d | 修改前引用 join 附近 BAR/WAIT_FLAG，随后尝试奇偶列分别写回；UB超限编译失败 | 明确的模拟器指导修改，失败分支仍应展示 |
| log10_ | 旧请求超时转用硬件指标；后续区域分析实验未超过固定起点 | 存在后续模拟器实验，不把早期收益倒归因 |
| uniform | 优化评测后模拟器确认32位指令与热点 | 事后机制核验，不是此前优化的触发证据 |
| negative_ | 存在模拟器文件，未核实对应修改决策 | 采集材料与实际指导分开记录 |
| rad2deg_、native_group_norm | 部分请求失败，另有共享或后续材料 | 不将请求或文件存在等同于指导成功 |

69个主图修改节点的饼图统计主来源标签，不包括全部历史分支；其中48项源码／IR标签均为事后推断。该图不能作为工具真实调用频率或性能贡献占比，更不能支持“26项没用模拟器”的结论。

## GQA从哪里继续

已有实验不重命名为全新起点：原始Triton候选SHA为`770910b7b720dd72ebf498d1baec91d0e254f032d1201da6316747bf290ca585`。既有有／无模拟器两组对照已完成，目标case4相对统一CANN参考约0.068×→0.094×；四项检查通过，不等于官方完整任务验收。现有模拟器数据为超时留下的局部窗口，且包含Codex代码审查反馈。

第一步冻结续接清单：从既有结果读取最佳候选完整SHA、父版本、官方checker提交、用例、dtype、seed、参考实现和计时参数；确认精度适用范围及既有系数审查问题。新一轮不覆盖旧目录或旧结论。

第二步对当前候选采集成对profiling及模拟器，优先解决现有局部窗口的覆盖问题。若仍只能采集有限窗口，记录窗口位置、核、循环范围及缺失范围；缩小输入仅作为机制实验，不能替代原目标case成绩。

第三步在修改前提出具体判断：例如剩余差距来自冗余计算，还是等待／搬运组织；只有实际证据支持时才选该问题。登记模拟器相对profiling和IR新增了什么信息，不预设一定能消歧。

第四步选择修改层：

- Triton可表达的布局、分块、调度和计算组织，优先改源码。
- Triton意图合理而生成IR存在具体低效时，设计单算子IR最小验证。
- 同类生成问题可重复且应普遍解决时，再设计通用pass；须有第二个形状或实例验证适用性。
- custom op／Ascend C继续作为独立能力扩展分支，不混入严格Triton结果。

第五步由CC／DeepSeek实施候选，Codex只分析与维护workflow。记录编译、正确性、完整调用耗时及设备耗时；重新采集预先指定的硬件指标，判断预期机制是否改变，随后保留或回退。

## 每轮必须保存的trace

复用现有公共trace/runtime和decision机制，不创建另一套不兼容日志。

| 时点 | 必须保存 |
| --- | --- |
| 修改前 | 父源码SHA、模型与预算、证据文件及SHA、提供／实际读取情况、替代解释、模拟器新增判断、主辅来源、修改层、预测与验证方法 |
| 修改后 | 子源码SHA与diff、模型输入输出、编译日志、实际IR与对应关系、失败原因、正式合同结果及成本 |
| 重新采集后 | 与同一源码绑定的profiling／模拟器产物、窗口范围、预期与实际变化、保留或回退理由 |

对照实验重新从共同冻结起点分支，两组保持相同模型、合同、非模拟器输入与最大预算；逐条记录额外人工反馈，避免只给一组纠错而未披露。统一绘制CANN加速比，同时保留原始耗时。每轮完成后立即更新图，不在最终汇报时补造归因。

交付：一个GQA完整案例图、关键流水窗口前后对比、修改层与生成代码变化、相对CANN结果及失败分支。若只实现Triton层优化，按实际报告，IR/pass作为下一步而非既成成果。
