## 使用与验证边界

已有配置的实例仍使用 `kg server start <name>`；首次远端配置按 [远端部署](../operations/deployment/remote_server.md) 操作。PPU 的 SSH 登录环境已是执行容器，使用 `--container -`；登录宿主机后还需进入 Docker 的机器使用真实容器名。燧原使用 `--backend enflame --devices <空闲物理卡号> --timing triton`，不使用 CUDA backend 别名。外部管理的系统 Python 遇到 PEP 668 时，使用继承厂商运行时的项目 venv，不破坏系统包保护、不升级 Torch/Triton/torch_gcu。

PPU 卡15与燧原卡7已分别完成真实 CLI 启动、status、幂等启动、doctor、stop，均只创建一个健康 slot；见 [PPU 配置复验](../validation/ppu_suiyuan_container_reconfigure_20260913.md) 和 [Enflame 单卡验收](../validation/enflame_cli_20260913.md)。这些真机证据来自记录中的修复前后 commit，不是新发布 tag 的完整模型优化 E2E。发布组合运行相关 host 回归，数量和最终 SHA 记录在 Gitee Release；没有重新执行多芯片模型生成，也没有处理此前按维护者要求暂缓的 22 项主线全量失败。

KG、KGS 和 Protocol 版本相互独立；协议兼容只看 `/status.api_version`，可选功能只看 capabilities。只读参考接口不改变 seed、Eval 或计时语义，Server 仍只监听 loopback，通过 SSH stdio proxy 访问。
