# KG v6.2.1 发布说明

KG v6.2.1 收录 SimpleOpt/KernelGen Workflow 小重构、验收和实验手册更新、KG 单向选择配套 KGS，以及 FlagGems 显式版本选择。本次按维护者明确要求更新配套 KGS 到 v6.3.1，并将已有 KG v6.2.1 tag 移到更新后的 HEAD，不另增 KG 版本号。最终 KG commit 由 annotated tag `v6.2.1` 指定。

推荐组合为 **KG v6.2.1 / KGS v6.3.1@7f1110be26e1d3a37195dbf5fee96cc99ca516bb / Protocol v6.2**。KGS repository、release 和 exact commit 以 [KG 锁定清单](../../deployment/kgs.lock.yaml) 为准。本次新发布 KGS v6.3.1，旧 KGS v6.3.0 tag 保持不变；不安装或升级 Torch、Triton、厂商运行时或实际部署中的 FlagGems。

## 兼容和升级边界

KG release、KGS release 和 Protocol version 独立。旧 KGS 的 `compatibility.yaml schema_version: 1` 仍可读取，但其中 `kernelgen_releases` / `latest_validated_kgs` 历史反向矩阵不再参与 KGS 选择；无需修改不可变的 KGS v6.3.0 tag 来登记 KG v6.2.1。精确 checkout、clean 状态及 Server 自描述与 KG 锁定清单匹配仍须通过，运行时只按 `/status.api_version` 和 capabilities 判断协议及可选功能。

FlagGems repository 和首次默认 revision 仍来自锁定 KGS 的 `frameworks.flaggems`，推荐 commit 为 `d64794e63b502cb836bc015a92a62c42de4be05a`。停止实例后可用 `kg server install-flaggems <name> --revision <分支或完整commit>` 显式选择其他版本，后续启动不自动追踪分支。KGS v6.3.1 的 Adapter Catalog 不再保存或校验固定 framework revision；实际 commit、测试源码和枚举结果继续参与 fingerprint，源码工作树、资产、ABI 和报告格式检查保留，更新后重新 inspect 和验证 baseline。Native Catalog 的冻结 oracle 仍要求 exact revision。

Catalog 与 Server 生命周期保持解耦。旧 campaign 续跑保留原 KG/KGS、framework 和输入快照；已有命名实例保留创建时的 KGS commit，即使 KG release 字符串仍为 v6.2.1 也不会自动升级。新实验使用按新锁定清单创建的新实例，不手工覆盖旧 checkout。

CLI 仍不支持 Batch 根目录 resume、直接接管旧 Python workspace，以及 `--operator-dir` 执行绑定；KGS Bundle 存储能力不等于执行绑定，`evaluation_binding=false` 不变。
