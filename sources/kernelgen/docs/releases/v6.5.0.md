# KG v6.5.0 发布说明

本次新增启动时准备 FlagGems 的可选参数，因此发布 minor 版本 v6.5.0，而不是 patch 版本 v6.4.1。包含 v6.4.0 之后已合入的抽取、审核、Knowledge 和 Analyzer 修订。旧 tag 不移动；KG 最终 exact commit 由 annotated tag `v6.5.0` 和发布 PR 记录。

配套为 KG v6.5.0 / KGS v6.3.4@a3112ba3fbf733fbb57d231292ce595fbec4e1a5 / Protocol v6.2。KGS commit 沿用主线 !147 的锁定值，本次不发布新 KGS tag，不修改 Protocol。新部署必须使用 [锁定清单](../../deployment/kgs.lock.yaml) 的 exact commit，不能用 KGS v6.3.4 tag 替代开发快照。KGS 历史反向兼容矩阵不决定配套版本。

## 使用变化

- `kg server start <name> --install-gems`（别名 `--install_gems`）在启动前复用现有安装流程准备 FlagGems，local/remote 均支持；已有配置复用已选 revision，不自动升级。运行中的实例尚未配置 Gems 时要求先停止，安装失败不继续启动。远端从 exact commit、clean 校验后的 KGS checkout 读取清单，不要求本地 KGS 仓库，也不要求远端先安装 YAML 解析依赖。显式选择版本仍使用 `install-flaggems --revision`。
- `kg run`、Batch 和统一 Python launcher 不再默认 Ascend910B。未指定 `--target-hardware` 时，CatalogOptimize 从 KGS `/status` 解析实际目标；显式约束不匹配或 Server 缺失设备信息时仍失败。请求及 history 顶层 `target_hardware` 可为 `null`，表示没有用户约束；实际评测设备以冻结快照和 ledger 为准。消费这些 JSON 的程序应接受此空值。

安装和最小示例见 [ONBOARDING](../ONBOARDING.md)，完整参数与状态语义见 [CLI 设计](../design/kg_cli.md)。已有实例和 campaign 保留原 KG/KGS/Gems/Catalog 快照，不自动升级或迁移；升级后的新任务使用新实例和新 workspace。受保护运行时不自动安装、升级或替换。
