## 使用方式与迁移

`kg run --mode simple_opt|kernelgen` 统一调用 CatalogOptimize，执行 `prepare_catalog → review_catalog → optimize → code_review`；mode 只选择内部优化器。安装式 Native 与本地 Native 支持两种优化器；Gems adapter 仅支持 SimpleOpt。本地 `--catalog-path` 自动打包上传，不向用户暴露 Bundle SHA256。独立 CatalogExtract 通过前台 `kg extract --flaggems-repo <checkout> --operator <operator>` 或 `kg extract --pr-url <url> --operator <operator>` 生产共享 Catalog（Python launcher 保留），由各目标分别优化，不新增常驻编排器。

删除 `ExtractAndOptimizeWorkflow/Input`、`kg run --mode extract_and_optimize`、其 `kg run --input` 路径及 Catalog Python launcher 的 `--workflow` 选择器。使用已有 Catalog 时直接调用统一优化入口；需要抽取时先独立调用 CatalogExtract。原组合 workspace 保留，查询及续跑使用创建它的原 KG 版本，不自动迁移。旧 simple_opt/kernelgen v1 CLI 请求仍按原 launcher 和 ledger 布局恢复；新任务保存 v2 请求，优化产物位于 `stages/optimize/work`。

`reference_code` 是任意语言的只读参考，不要求能通过；`seed_code` 是待验证的 Triton 候选。两者不替代 Catalog correctness oracle、timing baseline 或 ledger。取消、完整模型输出后的安全点、Coder lease 权重及 KGS slot 隔离不变。

入门命令见 [ONBOARDING](../ONBOARDING.md)，完整契约见 [KG CLI](../design/kg_cli.md)、[Catalog 输入](../design/workflows/catalog_input_sources.md)、[优化流程边界](../design/workflows/optimization_workflow_boundaries.md) 和 [抽取审核修订](../design/workflows/catalog_extract_review.md)。
