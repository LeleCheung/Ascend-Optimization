# KG v6.7.0 发布说明

本次把 KG 本地的 KGS 依赖收窄到独立 `kernelgen-server-client` 包；完整 KGS 仅在目标设备的 `kg server start` 阶段安装。推荐组合为 **KG v6.7.0 / KGS v6.5.0@1ebddd2f3c160a036c20fbed18986613e1992799 / Protocol v6.2**。KG、KGS release 与 Protocol 独立；运行时协议兼容只看 `/status.api_version`，可选能力只看 `/status.capabilities`。客户端包版本不是协议兼容信号。

完整 KGS 与客户端的职责边界、安装和验证见 [KGS v6.5.0 发布说明](https://gitee.com/BaaiAC/kernelgen_server/blob/v6.5.0/docs/releases/v6.5.0.md)。KG 安装按 [ONBOARDING](../ONBOARDING.md) 执行，不必为了运行本地 Agent 预装完整 KGS；远端仍由受管 `kg server start` 准备锁定的 exact checkout。运行中的 KGS 实例和已冻结 campaign 不自动升级，`kg resume` 沿用原快照。

[客户端拆包真机报告](../validation/kgs_client_split_gpu_e2e_20260925.md)记录 H20 默认 KernelGen 一轮真实后台 E2E：`review_tests=ACCEPTED`、Eval 36/36 `PASSED`、Profile `completed`、最终复验 `PASSED`；H20 与燧原的 Native Bundle 上传、绑定和 Eval 也通过。受测 KGS 功能提交为 `f51ad972`，并非最终 v6.5.0 tag 的元数据提交；本次发布只更新 KG/KGS 版本与精确锁定，不宣称最终 tag 在所有芯片重新跑过 E2E。发布门禁通过 **125 项相关 host 测试**，并在全新隔离 venv 中完成 `pip install -e .`：实际安装的客户端来自锁定 KGS commit `1ebddd2f`，没有安装完整 KGS、Torch、Triton 或厂商运行时；隔离导入路径下 `kg --help` 可用。H20 现存测试实例仍是旧功能快照，不会因打 tag 自动升级。

本次不移动旧 tag。发布分支为 `chore/release-kg-v6.7.0`；最终发布 PR、dev commit 与 tag 的对应关系记录在 Gitee Release。

发布后已在 H20 上对最终 tag 组合完成 1 round 真实 GPU E2E：完整 Workflow、36/36 候选 Eval、NCU Profile 与最终复验均通过。该验证晚于 tag 创建，不改变上文对发布收尾时验证范围的表述；实际结果、共卡性能限制和原始证据见 [最终 tag H20 验证报告](../validation/kg_v6.7.0_kgs_v6.5.0_h20_tag_e2e_20260925.md)。
