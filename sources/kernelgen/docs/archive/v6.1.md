# KernelGen v6.1：通用算子提交 Schema

## 结论

v6.1 定义了一种**通用的算子提交格式**：后续任何想把算子交给 KGS 优化的提交者，都按这种格式打包算子目录。FlagGems addmm_ 是第一个试点，验证设计是否成立。

核心原则：**KGS 是唯一计时权威**。提交者只声明算子的 ABI、reference 实现和输入规格，不带任何 benchmark harness。KGS 负责物化张量、执行 reference 和 candidate、计时。baseline 和 candidate 用同一把尺，加速比内部自洽，不需要和任何外部数字对齐——这也从根上消除了 v6.0 与 FlagGems 加速比对不上的 gap。

---

## 已确认的设计决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 评测契约 | 声明式自包含，复用 native adapter | 不需要新 adapter；外部提交者不带 harness |
| api_version | **暂不 bump**，保留 v6.0 | bump 会连带 207 个 JSON + 9 处 Literal + 8 个测试，成本不划算 |
| InputSpec 加厚 | **本次不做** | 构造复杂性（transposed layout 等）交给 `gen_inputs`，这是它本来的职责 |
| loader 历史欠债 | 留给后续收敛 | correctness_reference/effects.cases/call 字段、loader 分叉，本次不动 |
| 实现范围 | host 端改动 + 单测，暂不连天数 | tool-context 未就绪 |

## 一、目录布局（per-operator）

每个算子一个目录，固定文件名，manifest 不再枚举算子列表：

```
<catalog-root>/
  manifest.json                  # 包级元数据
  ops/
    <op_name>/
      definition.json            # 纯 ABI
      oracle.py                  # 可信正确性来源：REFERENCE_DEVICE + gen_inputs + run
      correctness.jsonl          # 正确性 workload
      timing.jsonl               # 计时 workload（core level）
```

### manifest.json

```json
{
  "api_version": "v6.0",
  "evaluator": "native",
  "layout": "per-operator"
}
```

`layout: "per-operator"` 是新字段，`catalog.py` 用它切换发现逻辑。不带此字段的 catalog 走现有路径，向后兼容。

### definition.json

纯 ABI，不含任何评测代码。仅保留：`name`/`description`/`parameters`/`outputs`/`effects`（只含 `mutates`/`returns_alias_of`）。`reference_device` 只允许通过同目录 `oracle.py` 的 `REFERENCE_DEVICE` 声明。

去掉现有 v6.0 数据里 schema 不认的字段：`correctness_reference`、`effects.cases`、`reference`（reference code 移到 oracle.py，由 loader 注入）。

### oracle.py

一个模块导出三样东西：

```python
REFERENCE_DEVICE = "target"   # 必需："target" 或 "cpu"

def gen_inputs(ctx, device):
    """
    有构造复杂性时（transposed layout、特殊初始化等）在这里处理。
    ctx["inputs"] 携带每个 input 的 spec，ctx["seed"] 供 Generator。
    返回 None 表示让 make_cpu_bases 的 random recipe 正常接管。
    """
    return None

def run(self, mat1, mat2, *, beta=1, alpha=1):
    """Reference 实现，ABI 与 definition.json 的 parameters 完全一致。"""
    return self.addmm_(mat1, mat2, beta=beta, alpha=alpha)
```

`gen_inputs` 是"构造复杂性的逃生口"：普通 randn 场景返回 `None` 即可；需要转置 mat2 时，直接 `return {"mat2": torch.randn([N,K]).t()}`。

## 二、Workload 格式

### 普通 random case（timing/correctness 标准格式）

```json
{"name": "addmm_-time-fp16-384",
 "inputs": {
   "self":  {"type": "random", "shape": [384, 384], "dtype": "float16"},
   "mat1":  {"type": "random", "shape": [384, 384], "dtype": "float16"},
   "mat2":  {"type": "random", "shape": [384, 384], "dtype": "float16"}
 },
 "seed": 0}
```

### safetensor case（真实 dump 输入 + golden output）

```json
{
  "name": "addmm_-real-fp16-4096",
  "input_path":  "/data/dumps/addmm_/fp16_4096_inputs.safetensors",
  "output_path": "/data/dumps/addmm_/fp16_4096_golden.safetensors",
  "inputs": {
    "self":  {"type": "safetensor", "shape": [4096, 4096], "dtype": "float16"},
    "mat1":  {"type": "safetensor", "shape": [4096, 4096], "dtype": "float16"},
    "mat2":  {"type": "safetensor", "shape": [4096, 4096], "dtype": "float16"},
    "alpha": {"type": "scalar", "value": 1.0},
    "beta":  {"type": "scalar", "value": 1.0}
  },
  "seed": 0,
  "tolerance": {"atol_scale": 4096.0, "required_matched_ratio": 1.0}
}
```

**语义：**
- `input_path`：tensor 参数从此 safetensors 文件按参数名为 key 读取；scalar 参数仍从 `inputs` recipe 读。
- `output_path`：跳过 reference code 执行，golden tensors 从文件读取；timing 的 gold latency 从文件 metadata 里的 `latency_ms` 字段读。
- `type: "safetensor"` 里的 `shape`/`dtype` 是文档字段，不做强校验，以文件中实际 tensor 为准。
- 路径使用**绝对路径**（考虑未来从 k3s 读取）。
- 无 `input_path`/`output_path` 时，退化为现有行为，零影响。

### safetensors 文件格式约定

使用 safetensors 的 `metadata` 参数存储标量 metadata（value 必须是字符串）：

```python
from safetensors.torch import save_file

# dump inputs
save_file(
    {"self": self_tensor, "mat1": mat1_tensor, "mat2": mat2_tensor},
    "/data/dumps/addmm_/fp16_4096_inputs.safetensors",
    metadata={"op_name": "addmm_", "dtype": "float16"}
)

# dump golden output（含 latency）
save_file(
    {"out": golden_out_tensor},
    "/data/dumps/addmm_/fp16_4096_golden.safetensors",
    metadata={
        "latency_ms": "3.14",     # float → str，读时 float(meta["latency_ms"])
        "op_name":    "addmm_",
    }
)
```

golden output 的 key 按 `definition.outputs` 顺序命名：单输出用 `"out"`，多输出用 `"out"`/`"out_1"` 等。

## 三、KGS 代码改动面

### 改动 1：`kernelgen_server/protocol/schema.py`

`Workload` 新增两个可选字段：

```python
class Workload(StrictModel):
    name: str = Field(min_length=1)
    inputs: Dict[str, JsonValue]
    seed: int = Field(default=0, ge=0, le=2**63 - 1)
    tolerance: Optional[Tolerance] = None
    input_path:  Optional[str] = None   # 新增：输入 tensor safetensors 绝对路径
    output_path: Optional[str] = None   # 新增：golden output safetensors 绝对路径
```

### 改动 2：`kernelgen_server/evaluation/operator_adapter.py`

`make_cpu_bases` 里，处理完普通 recipe 后，若 `workload.input_path` 存在则覆盖 tensor 类型的值：

```python
# 在现有 recipe 处理之后追加：
if getattr(workload, "input_path", None) is not None:
    from safetensors import safe_open
    with safe_open(workload.input_path, framework="pt", device="cpu") as f:
        for key in f.keys():
            values[key] = f.get_tensor(key)
```

同时在 `_recipe` 里识别 `type: "safetensor"`（遇到时跳过，留给 input_path 路径处理）：

```python
if kind not in {"random", "custom", "scalar", "literal", "safetensor"}:
    return None
```

### 改动 3：`kernelgen_server/evaluation/engine.py`

**correctness 分支**（`_correctness_gate:147` 附近），在 reference call 前插入：

```python
if getattr(workload, "output_path", None) is not None:
    from safetensors import safe_open
    golden = {}
    with safe_open(workload.output_path, framework="pt", device="cpu") as f:
        for key in f.keys():
            golden[key] = f.get_tensor(key)
    ref_outputs_list = [golden[k] for k in request.definition.outputs if k in golden]
    reference_output = ref_outputs_list[0] if len(ref_outputs_list) == 1 else ref_outputs_list
else:
    try:
        _seed_globals(workload.seed)
        reference_output = reference_function(*reference_call.args, **reference_call.kwargs)
    except Exception as exc:
        reference_error = exc
```

**timing 分支**（`evaluate:283` 附近），若有 `output_path` 则跳过 reference timing，读 gold latency：

```python
if getattr(workload, "output_path", None) is not None:
    from safetensors import safe_open
    with safe_open(workload.output_path, framework="pt", device="cpu") as f:
        meta = f.metadata() or {}
    gold_latency = float(meta["latency_ms"]) if "latency_ms" in meta else None
    # 只跑 candidate
    candidate_invoke()
    self.device.synchronize(self.device_string)
    candidate_latency = self.device.time(
        candidate_invoke, [], request.settings.warmup_ms,
        request.settings.benchmark_ms, self.device_string,
    )
    result = TimingResult(
        status=WorkloadStatus.PASSED,
        latency_ms=candidate_latency,
        reference_latency_ms=gold_latency,
        speedup=gold_latency / candidate_latency if gold_latency else None,
    )
else:
    # 现有逻辑不变
```

### 改动 4：`kernelgen_server/catalog.py`

`Catalog.__init__` 里新增分支，当 manifest 含 `"layout": "per-operator"` 时切换发现逻辑：

```python
if self.manifest.get("layout") == "per-operator":
    ops_root = self.root / "ops"
    for op_dir in sorted(ops_root.iterdir()):
        if not op_dir.is_dir():
            continue
        entry = self._load_per_op_entry(op_dir)
        entries[entry.definition.name] = (op_dir.name, op_dir / "definition.json", entry.definition)
```

新增私有方法 `_load_per_op_entry(op_dir: Path) -> OperatorData`，与现有 native 分支逻辑镜像：

```python
def _load_per_op_entry(self, op_dir: Path) -> OperatorData:
    def_path = op_dir / "definition.json"
    oracle_path = op_dir / "oracle.py"
    corr_path = op_dir / "correctness.jsonl"
    timing_path = op_dir / "timing.jsonl"
    for p in (def_path, oracle_path, corr_path):
        if not p.is_file():
            raise ValueError(f"missing per-op asset: {p}")
    definition = Definition.model_validate_json(def_path.read_text(encoding="utf-8"))
    oracle_source = oracle_path.read_text(encoding="utf-8")
    reference_device = "target"
    for line in oracle_source.splitlines():
        if line.strip().startswith("REFERENCE_DEVICE"):
            _, value = line.split("=", 1)
            reference_device = value.strip().strip("\"'")
            break
    definition = definition.model_copy(update={
        "reference": oracle_source,
        "reference_device": reference_device,
    })
    correctness = self._load_workloads(corr_path)
    timing = self._load_workloads(timing_path) if timing_path.is_file() else []
    if not correctness and not timing:
        raise ValueError(f"operator has no workloads: {op_dir.name}")
    return OperatorData(op_dir.name, op_dir.name, definition, "native", correctness, timing)
```

## 四、addmm_ 试点数据

### 目录结构

```
kernelgen_server/data/flaggems-v6.1/
  manifest.json
  ops/
    addmm_/
      definition.json      # 纯 ABI，去掉 correctness_reference/effects.cases
      oracle.py            # REFERENCE_DEVICE + gen_inputs(return None) + run
      correctness.jsonl    # 36 条（3 dtype × 4 scalar × 3 MNK shape）
      timing.jsonl         # 15 条（3 dtype × 5 shape，core level，天数实测确认）
```

### addmm_ 语义（来自 FlagGems 源码）

- 调用序：`(self=[M,N], mat1=[M,K], mat2=[K,N])` + keyword-only `beta`/`alpha`
- correctness：3 MNK shapes × 4 SCALARS × 3 dtypes = 36 条，`alpha=beta=scalar`，`atol_scale=K`
- timing（core level）：5 shapes × 3 dtypes = 15 条，alpha/beta 用默认值，`b_column_major=False`
- core shapes（`BlasBenchmark`，忽略 B）：`[384,384,384]`、`[4096,4096,4096]`（×2）、`[1024,1024,1024]`、`[2048,2048,2048]`

### 提取命令

提取器从 FlagGems accuracy 源码读取完整 `MNK_SHAPES` 和 `SCALARS`，并通过原生
case-list 接口枚举 timing workload：

```bash
python3 examples/flaggems_v61_extract/run_example.py \
  --operator addmm_ \
  --flaggems-repo /path/to/FlagGems
```

默认输出到 sibling Server 仓库的
`kernelgen_server/data/flaggems-v6.1/`。只有在隔离测试或显式生成其他 catalog 时才传
`--catalog-root` 覆盖该路径。

默认在 FlagGems checkout 中执行：

```bash
python3 -m pytest benchmark/test_addmm_.py \
  --level core \
  --list-cases \
  --output <temporary-case-list.json> \
  -q
```

若开发机没有目标 Torch/厂商运行时，可以先在目标环境保存同一
`flaggems.benchmark-case-list/v2` JSON，再通过
`--case-list-path /path/to/cases.json` 完成打包。提取结果保留原始 `case_id` 作为
Native timing Workload name，不重新编号或去重。
