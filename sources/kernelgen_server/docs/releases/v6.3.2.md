## 兼容与部署

Protocol 仍为 v6.2，继续支持 v6.0 Catalog。协议检查只读取 `/status.api_version`，功能只读取 capabilities。上传的 Native Operator Bundle 现在支持执行绑定，详见 [Bundle 接口](../operator_bundle_upload.md)；不能把旧 v6.3.1 的 `evaluation_binding=false` 当成当前事实。

ALL_SKIP 表示全部 correctness 被跳过，仍可继续 benchmark，不等于正确性通过。Adapter 不绑定 Gems revision；冻结 Native oracle 的 exact revision 约束保持不变。历史 compatibility 反向推荐表不是新部署依据。运行时依赖、设备隔离和旧 campaign 快照策略不变，升级不自动替换 Torch、Triton 或厂商运行时。部署见 [部署教程](../multiple_device_deploy_tutorial.md)。

## 验证边界

发布前功能基线为 `c309cb351d2a473e79dcad80a90df4363d5b9fb7`，与之前昇腾下游 E2E 使用的 KGS commit 一致。该 E2E 使用准备好的 relu Catalog，跳过抽取和 Catalog Review，真实执行上传、readiness、两轮 SimpleOpt、最终复测和代码 Review；不是完整来源抽取验证，也不是新增 Catalog 的逐算子验收。KG 侧证据见其 `docs/validation/workflow_build_ascend_20260913.md`。
