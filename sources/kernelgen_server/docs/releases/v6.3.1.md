# KGS v6.3.1 发布说明

本次 patch 发布解除 FlagGems Adapter Catalog 对 Gems commit 的重复绑定，配套组合为 KG v6.2.1 / KGS v6.3.1 / Protocol v6.2，验证范围为 host。KGS 发布 commit 由 annotated tag `v6.3.1` 指定，并由 KG 的 `deployment/kgs.lock.yaml` 锁定；KG、KGS 和 Protocol 版本相互独立，KGS v6.3.0 tag 保持不变。

## 兼容和升级边界

FlagGems 由 KG 实例或操作方选择，首次默认推荐值仍为 `compatibility.yaml` 中的 `d64794e63b502cb836bc015a92a62c42de4be05a`；可显式选择同一仓库的其他 commit。旧 Adapter manifest 的 framework 字段不再限制执行。每个 campaign 仍固定实际 checkout，不自动跟随分支；源码/pytest 配置必须干净，测试资产、ABI 和报告格式必须兼容。实际 commit 继续参与 benchmark fingerprint，Profile 拒绝 inspect 后 fingerprint 改变的请求。

FlagGems-backed Native Catalog 的冻结 oracle 继续要求 exact revision。本次不改变 Native oracle、设备 slot、取消流程或 wire protocol；Protocol 仍为 v6.2，并支持 v6.0 Catalog。Bundle `evaluation_binding=false` 不变。KG 只按 `/status.api_version` 和 capabilities 判断运行时协议及功能兼容；KGS 历史 `kernelgen_releases` 条目保留作历史记录，不用于反向限制新的 KG release。

旧 campaign 不自动升级 KGS/Gems 或更换 Catalog；新实验由更新后的 KG 锁定清单部署 KGS v6.3.1，不手工覆盖旧实例 checkout。

## 验证范围

功能提交已通过 KGS host suite：324 passed、28 skipped，以及配套 KG host suite：1099 passed。测试覆盖新/旧 Adapter Catalog 使用不同实际 commit、fingerprint 变化、stale Profile 拒绝、Native exact 拒绝、dirty 源码/pytest 配置、缺失测试资产，以及 wheel 打包后的 manifest。发布候选会复跑相同门禁，实际结果与精确提交记录在发布提交、annotated tag 和 Gitee Release。

跳过项主要依赖未安装的 Torch 或显式启用的 GPU E2E。本次不安装或升级依赖，不启动 GPU/KGS/远端 SSH；历史真机结果不作为本次发布 commit 的新增 E2E 证据。
