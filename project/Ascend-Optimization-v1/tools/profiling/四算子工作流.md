当前实现是 **Markdown 知识＋Python/Bash 控制器＋CC/DeepSeek** 的无人值守工作流，尚未封装为标准 skill。公共入口为 `run-four-operator-workflow.sh` 与 `four_operator_workflow.py`，固定源码配置为 `four-operators.json`，知识为 `工作流通用知识.md` 和各算子的 `优化知识.md`。

最终成绩见[四算子交付](../../operators/四算子工作流交付-20261014.md)，失败和未采纳结果也保留。历史最佳源码复跑与模型重新生成分别报告。

## 第二步：选择模式并启动

每次新测量换一个批次名和 tmux 会话名。完整执行源码复现与方法生成：

```bash
p=/data/hanle/ascend-optimization/Ascend-Optimization/project/Ascend-Optimization-v1
tmux new-session -d -s profiling-four-example \
  "bash $p/tools/profiling/run-four-operator-workflow.sh example all 2 > /data/hanle/ascend-optimization/runs/four-example.log 2>&1"
```

参数顺序为 `<新批次名> <all|replay|method> <每项生成轮数> [已有复现批次名]`：

| 模式 | 行为 |
|---|---|
| `replay` | 四个历史最佳源码完整评测、采集诊断、同源码两次最终复验；不调用模型 |
| `method` | 从固定优化前源码自动采集、调用 CC、生成候选、完整评测和最佳选择，最终复验两次 |
| `all` | 先串行执行四项 replay，再串行执行四项 method |

每算子生成轮数允许 1—6，默认3；每轮模型调用20分钟超时，完整评测30分钟超时。单次 CC 只返回源码和理由，控制器自动启动后续轮次、反馈失败、完整测试并保留最佳，不需要人工逐轮调用。

已有 `20261014-four` 的完整源码复验，想仅运行新的生成批次并汇总旧复验：

```bash
tmux new-session -d -s profiling-four-method-example \
  "bash $p/tools/profiling/run-four-operator-workflow.sh example-method method 2 20261014-four > /data/hanle/ascend-optimization/runs/four-example-method.log 2>&1"
```

第四个参数只选择汇总来源，不重复设备复验；各列保留自己的批次与合同，方法收益只比较同一方法批次的起点与最终。

## 第三步：理解输入和采纳规则

| 算子 | 固定优化前起点 | 固化建议 |
|---|---|---|
| logaddexp2 | 固定 master | 稳定公式、精度安排、连续快路径、去 mask、多 tile 与规模分流 |
| amin | 历史 v5 | 整除去 mask、输入精度归约与 FP32 回退、多缓冲 |
| matmul_bias_activation | 历史 v9 | FP32 双 N tile 复用 A、BK128；保留半精度路径 |
| narrow_copy | 历史 KG 有 profiler 纯 Triton 版 | 小输入真实 CANN DMA，大输入保留 Triton |

这三个历史中间起点用于验证后续建议，未声称四项都从 master 自动重新发现全部优化。模型获得起点源码、真实逐 case 延迟、两个慢 case 的真机 PipeUtilization、语义诊断、专用知识和失败历史，未直接提供完整最佳源码。

正式采纳要求完整合同通过，且较当前最佳提升超过0.5%；最终方法有效还要求真实实现变化、采纳记录，以及两次最终复验较慢值相对起点超过0.5%。新生成检查拒绝只改注释/排版、未接入的新函数和调用占位符；静态检查不替代完整测试和源码审查。

方法模式使用 `--provider-thinking disabled`，临时 loopback 转发器显式向供应商发送 `thinking: disabled`，随单次模型调用结束，不修改全局 Claude 设置。审计保存模型、路由、请求摘要和 HTTP 状态，不保存凭据。原问题见[生成接口说明](DeepSeek生成接口修复-20261014.md)。

## 第四步：查看、恢复和下载

```bash
tmux attach -t profiling-four-example
cat "$p/operators/narrow_copy/reports/profiling-agent-example-method/campaign-state.json"
```

按算子产物在 `operators/<算子>/reports/profiling-agent-<批次>-replay/` 或 `-method/`，日志在同级 `workflow-<批次>-<模式>.log`。保存知识快照、提示词、模型响应、候选、诊断、原始附件、逐 case 结果和两次最终复验。

同批次再次执行会恢复已完成步骤；已发出的未知结果请求不会自动重发。先查实际进程、KGS 请求和日志，不因 SSH 返回 `no available gateway` 就重启队列。运行期间不得修改知识、源码或 commit/pull：仓库 HEAD 参与合同指纹。已完成批次只读复用，新测量换批次名。

在控制端仓库根目录下载已完成证据：

```bash
python project/Ascend-Optimization-v1/tools/control/control.py \
  --host baai-910b --remote-root /data/hanle/ascend-optimization \
  download --batch example --operators logaddexp2 amin matmul_bias_activation narrow_copy
```

控制工具不将仍在运行的 campaign 下载为正式交付证据；控制器启动命令、清单和完整运行日志另随实际批次归档。

## 第五步：离线核验与复现

下载全部结果后，在控制端项目目录执行，不连接设备或模型：

```bash
python tools/profiling/four_operator_workflow.py --batch example --report-only --require-complete
```

最新交付由 `20261014-four` 的四项源码复验与 `20261014-four-refined` 的四项方法生成组成；后者每项两轮：

```bash
python tools/profiling/four_operator_workflow.py --batch 20261014-four-refined \
  --mode method --replay-batch 20261014-four --report-only --require-complete
```

汇总核验完整合同、起点和最终源码 SHA、模型来源、知识快照、最佳选择、两次复验与真机附件。缺项时停止交付汇总。可追加 `--method-batch 算子=批次` 明确选择重试来源，不发起新运行。

若需原样使用某个历史生成实验的知识，对 `optimization_campaign.py` 传入 `--knowledge <旧campaign>/knowledge.md --knowledge-snapshot`；该选项直接使用旧全文，不再拼接当前知识。模型重新生成可能不同，固定源码 replay 用于复现既有表现。

加速比取完整性能 case 的几何平均，最终取两次复验较慢值。当前分析使用真实延迟、PipeUtilization、语义和源码约束，数值 Roofline 尚未建立。首批与重试的失败日志保留在各自报告目录，源码复现不计为模型新生成成果。
