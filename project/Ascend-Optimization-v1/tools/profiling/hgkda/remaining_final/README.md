## 起点与验收

- `fix` 同源码三次为0.892、0.803、0.766倍，尚不计稳定达标；不靠继续重测挑高分。
- `expm1_` 为0.697倍，完整正确性和小值精度检查通过，大输入需要优化。
- 新候选必须通过原完整合同、原扩展补测和24项对齐原生路径检查。选定源码固定一次确认；低分和失败全部保留。
- 本轮采用自写Ascend C计算和特殊布局Triton回退，Codex编写与诊断的贡献明确登记。

## 实验方向

1. 根据逐case完整调用和独立设备记录区分小输入宿主成本与大输入设备成本。
2. 将4096元素输入/输出双队列方案，与更大分块、复用读入缓冲的方案比较。显式MTE2→Vector→MTE3事件保证依赖，避免FP32计算后再复制到另一个片上输出缓冲。
3. 保留expm1接近零的短级数、特殊值与有符号零，不使用简单exp(x)-1替代全部输入。
4. 最佳源码通过KGS后，用新形状独立检查，记录方法选择及验证结果，形成统一入口可读取的诊断记录。

所有设备任务取得项目物理卡7串行锁；不修改共享服务、镜像和锁定上游。源文件、请求、结果和附件绑定SHA，不覆盖前批。

## 入口

`prepare.py`冻结合同，`build.py`和`make_proposals.py`构建设备变体；`build_*host.py`和对应`make_*proposal*.py`保存独立宿主实验；`run.py`在tmux持卡锁评测待处理提案，已完成请求不重发。`remaining/reproduce.py --batch remaining-final-20261031 --operator 算子名 --run-name 新名字`只做一次独立复现，不改历史最佳。`finish.py`读取固定确认结果，做冻结新形状、同输入设备trace和真实Triton IR收尾，不追加性能重测。

统一离线诊断入口为skill内的`analyze_execution_paths.py`。它计算逐case差距、候选/参考各自耗时变化及下一项验证方向；复杂源码机制和后端选择本批仍由Codex分析。自动生成诊断不等于已证明原因。
