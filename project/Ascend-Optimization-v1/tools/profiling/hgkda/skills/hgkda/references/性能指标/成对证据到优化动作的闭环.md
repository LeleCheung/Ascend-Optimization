# 成对证据到优化动作的闭环

适用：已有正确源码、可固定输入和环境，准备由Agent调用证据工具并选择下一项优化。入口为tools/profiling/hgkda/agent_demo。

## 可复用方法

1. 先核对候选与参考实际执行路径、源码和输入身份。组件指标与完整算子成绩分别列示。
2. 模型选择需要的证据工具，再让脚本返回原始数据的结构化结果。源码、IR、数值Roofline和指令热点分别标明计量范围。
3. 将诊断变成有限、可验证的动作及预期指标。已有模板与历史成功经验作为显式先验，不称盲发现。
4. 用开发集合选择候选，正式前冻结。每源码一次完整KGS，并通过补充布局／精度／stream检查。
5. 对新源码重新采集，检查“预期变化”是否真实发生。模型回看结果后，由确定性证据核验确认可写入知识的事实。

## 2026-10-27矩阵乘演示

共享B候选与历史成功源码同字节。本批新模型调用主动读取源码、IR、热点、指标和知识，选择共享B及交错加载。共享B开发六组1.043×，交错1.008×；共享B进入正式评测，15项实际延迟比1.023×，两版42/42及18＋24补充检查通过。

新采集显示GM／L2／L1总量基本不变，但UB Read + Write约0.831×、Vector Read UB约0.727×、AIV MTE2指令数0.818×、平均搬运粒度1.217×。bcmlir静态copy／alloc由5处降至4处。这些是局部数据组织改善的证据；不能说全部层次流量不变，也不能将4处静态copy当作4次动态搬运。

起点和候选分别提取1087／926条模拟器指令，983／862条有源码位置；子进程计算导出后退出139，按部分证据保存。debug映射指向Python行只说明编译来源，例如B指针表达式映射到MTE2指令，不证明“指针加法本身花了4.52微秒”。

## 本批发现的模型错误

- 两种方案都通过开发门禁，不代表两种都完成正式评测。交错方案未进入正式验证，不能替它补正式成绩。
- 不能把1024单项预测区间与15项总体成绩相互替代；profiling时间也不替代正式时间。
- “GM／L1不变”不能泛化为“所有片内搬运量不变”；本批UB有明确变化。
- K循环交错加载不自动消除尾处理WAIT；热点仍在时，保留未证实预测。
- AIC搬运指令数未下降时，拒绝“减少B面板总请求”的直接因果解释。
