# 逐元素与原地计算

2026-10-31的`remaining-final-20261031`补充：fix采用保留同stream任务队列、C++分配输出时释放GIL的`queue-gil-v12`，固定两次0.848×/0.875×；expm1_采用大分块、复用读入缓冲写回及下一块预取的`prefetch-large-v8`，固定两次0.889×/0.868×。两项均完整30/30，原扩展、24项原生路径及30项冻结新形状通过；具体源码、请求、附件身份见本批`delivery.json`与`knowledge/records-final.json`。早期停滞与低分记录保留，不能把新宿主路径的通过倒写为旧路径通过。

后端、分块与缓冲须逐对象实测：expm1_预取版入选，fix预取版仅0.680×；fix直接宿主启动版约0.446×，保留队列并释放GIL版本才过线。`analyze_execution_paths.py`将逐case候选耗时和参考耗时变化分开计算；expm1_预取版相对事件版候选几何平均耗时比约0.975，参考约1.263，因此分数提升不能全部归为预取代码收益。独立设备区间与完整调用窗口不直接相减为精确宿主成本；大小输入差距只用于提出下一项验证假设。

对连续输入先检查每 program 工作量、网格上限、地址计算与读写量。非连续输入保留正确的 stride 路径；原地操作必须返回同一存储并保留修改语义。

SELU、log 等函数检查计算公式、输入范围和中间精度。数学等价不保证浮点结果满足测试，exp/log 指令也不能简单按普通 FLOP 计量。共轭操作保留复数虚部符号、共轭标志及实数行为。

边界掩码只在公开 shape 和 tile 可证明整除时移除，非整除仍保护。报告同时记录正确性通过与专家评审状态。

固定迭代 grid-stride 方案必须分别证明覆盖和不越界：设 program 数为 G、块大小 B、迭代次数 I，连续编号方案有掩码时要求 G×B×I≥N，无掩码时要求 G×B×I=N。仅有 N 整除 B×I 不能证明安全，因为实际 G 可能被下限或上限改写。rad2deg_ 首轮曾在 N=1025 漏算尾部，并在 N=2050×16384 的规划中产生越界范围；未将越界反例提交设备执行。

原地操作不能通过将 A 替换成 A.contiguous() 后返回复制品来处理非连续输入。补充检查应包括返回同一对象、原存储被修改、带步长切片和奇数长度；仅通过当前连续合同用例不足以覆盖这些语义。

多个 Vector/MTE 指标都高时，应检查是否重叠、是否重复搬运以及任务粒度；不按最大百分比直接下瓶颈定论。

2026-10-22的log10_/selu_使用成对硬件证据检查启动路径；当前输入地址与当前stream每次读取，完整stride不截断到固定8维。小输入优先减少宿主参数处理，大输入单独检查分块和UB。log10的低精度数学要通过IR确认实际类型转换已消失；SELU的FP16可行分块不能直接套给BF16/FP32。方法及工具见[成对对照与机制定位](../性能指标/成对对照与机制定位.md)。

2026-10-29的negative_补测发现：正式30项合同通过的负号候选，仍把`+0`的负号结果写成`+0`，与目标NPU PyTorch的`-0`不同。当前安装版Triton的普通和Ascend专用`semantic.py`均将一元负号实现为`0-x`，实际TTIR也已出现该表达式。不能将此现象直接归因于Ascend后端新增优化。浮点符号位翻转是待评测替代方式；FP32分块32768的翻转候选触发UB溢出（需求384 KiB、可用192 KiB），缩块后必须重新完整测试。普通数的数学等价不覆盖正负零；检查以目标NPU oracle为准，CPU结果旁列。证据见新25项批次的negative_成对采集、NPU补测和逐case正式结果。

本批hardswish的large-ub-tile-v5仅27/30：大输入把2字节存储分块增到16384、4字节增到8192，实际编译出现UB溢出，日志示例需求3,670,272 bits、可用1,572,864 bits。FP32中间值及后端multi-buffer会增加缓冲；不能按输入dtype字节数推断可用tile。失败原件位于该提案的assessment/formal。4096分块的已验证版本仍保留；直接改用原生低精度也更慢，不能默认降精度就会提高吞吐。

本批fmod_tensor_的CPU IEEE余数候选虽正式30/30，补测仅36/57。固定NPU参考对负数整除的零符号、有限数对无穷大取余等行为与CPU不同。npu-quotient-contract-v3用商→向零截断→乘法→减法，并避免乘减融合，已30/30、57/57，完整调用0.653×。CPU/NPU/候选向量随检查保存；这是本机参考兼容结果，不宣称已解决CPU IEEE语义或达到0.8×。后续不得靠删除这些特殊值或改容差获得通过。

2026-10-30接续批次 `remaining-nine-20261030` 新增来源可见的 Ascend C 候选，特殊布局保留历史 Triton 回退。`negative_`、`log2_`、`round_out`、`special_round_out`、`hardswish`、`fmod_tensor_` 在同源码两次完整合同、原扩展补测及24项对齐路径检查中均通过0.8×门槛。方法是 C++ 同 stream 任务队列启动，结合逐算子选择的流式分块或双缓冲队列。不能归纳为“双缓冲普遍更好”：log2_和special_round_out最终选择较大分块同步版，其他对象才选双缓冲版。精确成绩和附件身份以该批 `delivery.json` 为准，不把本条经验当作其他版本的性能证明。

启动与设备计算分别判断。该批小输入negative_的独立设备kernel未必比起点快，完整调用改善还涉及宿主路径；不得只根据完整调用分数宣称硬件指令减少。自写Ascend C与直接调用CANN厂商目标库分别记账，混合实现不称为纯Triton成果。

补充门禁要真的覆盖快速路径。旧的短向量特殊值检查可能因长度或地址限制走Triton回退；新增1024元素对齐输入、offset序列0/1/3/0、换数据与stream，检查原地/out别名和输出独立性。`expm1_`近零相对精度与零符号继续约束，约0.70×的正确实现仍未达标；不能用近零不准确的简化公式换成绩。

稳定性也属于交付门禁。`fix`三次完整结果约0.892×、0.803×、0.766×，三次几何平均约0.819×，仍因追加确认低于0.8×而不计稳定达标。重复结果保留，不通过追加高分覆盖低分。早期C++内部分配输出版本发生本批隔离worker停滞，后续Python `new_empty`分配再交C++启动的版本可运行；这是已观察的路径差异，运行时内部具体原因尚未确证。
