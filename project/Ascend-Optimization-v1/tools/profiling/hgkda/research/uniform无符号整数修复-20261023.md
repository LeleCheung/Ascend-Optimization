# uniform：从设备整数反例到标准 Philox 修复

固定 FlagTree `0.6.0+ascend.gitc286cba6`、CANN 9.0.0、910B4、物理卡 7。本次发现的是该软件栈上已测输入的无符号运算反例，不推广所有 Triton 或昇腾版本。

## 诊断证据

手写随机数候选通过 KGS、区间统计与随机状态检查，却未通过独立标准 Philox 逐位核验。先修复两个源码问题：Weyl 常数应为 `0x9E3779B9`，乘法低字应按半字拼接；同时统一 CPU 与 NPU 的输出排列。仍未解决全部不一致，因而继续拆到整数原语。

`probe-uniform-integer.py` 在 64 组确定性输入上分别测十种运算，独立 Python 整数作为参考：

| 原语 | 不匹配数 | 结果 |
|---|---:|---|
| 32 位乘法低字、16 位部分积、加法、异或、与、或、左移 | 0/64，各项 | 本探针通过 |
| `uint32 >> 16` | 30/64 | 有符号位的输入被算术右移 |
| `umulhi` | 63/64 | 与无符号乘法高字不同 |
| 原手写 16 位拆分的高字 | 63/64 | 拆分仍依赖出错的逻辑右移 |

最小见证之一：`0x80000000 >> 16`，期望 `0x00008000`，实际 `0xffff8000`。真实编译中间表示、二进制与反例均保存于主批 `research/uniform/integer-primitive-probe.json` 和对应 `-ir/` 目录。中间表示仍含整数 `muli`／`shrui`，没有证据支持“转浮点乘法导致误差”的解释。

## 修复

在 16 位拆分的四处移位中，显式将位模式转成 `int32`，再执行算术右移并掩码：

```python
high16 = ((value.to(tl.int32, bitcast=True) >> 16) & 0xFFFF).to(tl.uint32)
```

掩码对于有符号移位在语义上必需，避免依赖后端出错的无符号移位。修复后，手写 Philox 的 16 组独立设备核验全部通过；内置 `tl.philox` 另列对照仍失败，不用它充当正确参考。

第一次完整 kernel 编译又暴露 counter 进位比较 `new_c0 < c0` 触发不支持的 `uint32_t_to_uint64_t_rintmode`。改用同义位运算进位：

```python
new_c0 = c0 + lane
carry_bits = (c0 & lane) | ((c0 | lane) & ~new_c0)
carry = ((carry_bits.to(tl.int32, bitcast=True) >> 31) & 1).to(tl.uint32)
c1 = c1 + carry
```

进位恒等式先通过 100,004 组 CPU 整数见证，随后进入真实设备与完整算子检查。源码生成由 `prepare-uniform-shift-repair.py` 限制为已审查的 `_mul_hi_lo` 和 `uniform_kernel` 两个函数，状态读取、分块与启动策略继续复用 CC 生成方案。

## 验收与复现

最终副本 SHA：`3f6831d6b936d0e0b848c4d7b8dfdc18efe674e1baba87c858ab44a607316cd8`。独立 Philox 逐位 16/16、补充语义 18/18、随机状态 3/3、完整 KGS 18/18 通过，完整调用加速比 **1.325×**。这些有限核验覆盖已登记高位状态和 counter 跨界，不是完整随机质量认证。

原主批 **1.497×** 源码存在机制错误，不能作为标准算法正确的最终版本。最终源码及原始证据见[修复批次](../../../../operators/campaigns/endurance-20261022-uniform-shift-repair-v2/精简汇报.md)。

复用入口：`check-uniform-philox.py` 做逐位设备核验；`probe-uniform-integer.py` 做有限整数原语见证；`run-uniform-shift-repair.py --parent-batch endurance-20261022 --variant v2` 展示本轮完整控制流程。已存在批次不得原名重跑，以免覆盖证据；新实验须建立新批次，保持卡锁和固定环境。

CC/DeepSeek 贡献为原始探针、向量化随机数、区间处理与低开销启动。Codex 贡献为独立 CPU／设备参考、整数原语定位、常数与移位／进位修复，以及控制、完整验证与归档。这个实例固化的是从反例缩小到具体机制的诊断方法。
