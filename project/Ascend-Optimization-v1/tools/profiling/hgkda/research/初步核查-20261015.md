# 下一阶段初步核查

## 固定基线

逐文件核对固定 FlagGems 的 6,352 项，全部匹配清单。两个 KGS 声明的编译器均为 FlagTree `0.6.0+ascend.gitc286cba6`，Triton 3.5.1、CANN 9.0.0、驱动 25.2.0。首次检查时两服务健康空闲，物理卡7串行使用。

KGS 服务身份来自实际运行服务的 `/status`，原始记录见 [19655](kgs-status-20261015-19655.json) 和 [19657](kgs-status-20261015-19657.json)。容器的旧 distribution 元数据与显式源码运行的 KG/KGS release 不同，不能用无 PYTHONPATH 的裸包元数据替代当前服务版本。

## DMA 是否调用 PyTorch 复制

对历史最终 narrow_copy 候选执行独立进程核查：准备 `[16,8]` FP32 输入，复制行区间 `[3,8)`。执行候选前临时阻止 `Tensor.copy_`、`torch.narrow_copy` 与 `Tensor.narrow_copy`，同时观测直接绑定的 CANN 函数。

结果通过：唯一调用为 `libacl_rt.so` 的 `aclrtMemcpyAsync`，容量与复制量均160字节，D2D枚举3、返回码0；输出独立分配，并与 CPU 参考逐值一致。见[原始核查结果](dma-direct-audit-20261015.json)。该结论针对小型连续 DMA 快路径；其他分支和回退单独讨论。张量分配、地址及 stream 获取仍使用 PyTorch 元数据接口。

复用工具为 [audit-dma.py](../audit-dma.py)，在已取得物理卡7锁的独立容器进程执行，不改变共享服务或其他进程中的 PyTorch 行为。

## TLE Raw 与当前版本

固定 [PR #1238 的身份与文件列表](tle-raw-pr1238-20261015.json)。本次读取时未合并，head 为 `163a6f69ae36c14e2a4dd342062078542ed3158d`。它连接 kernel 内的 AscendC 外部操作，使用 `tle_raw.call` 或 `@dialect(name="cann")`；当前安装版本未提供该 PR 的统一 `triton.experimental.tle.language.raw` 入口。

宿主侧运行时复制与 kernel 内的 AscendC 数据搬运不是同一调度路径。后续另设新编译器实验组验证最小 TLE Raw 操作，再评估复制性能；不能仅换入口名就宣称已保留 DMA 收益。本轮未升级 FlagTree。

## KG 接入核验

独立覆盖层使用原固定 KG 源码，扩展两种原生 profiling 角色并加入项目内 HG-KDA skill。容器中加载21个角色成功，工具合同保留；原生物化器同时生成 Claude 和 Codex skill 目录，见[加载核验](kg-overlay-check-20261015.json)。这证明接入文件与角色可加载，真实模型是否执行阶段采集仍需相应实验记录，不能以加载通过代替性能闭环。
