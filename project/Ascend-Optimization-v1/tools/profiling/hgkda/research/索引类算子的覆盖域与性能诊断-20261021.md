# 索引类算子的覆盖域与性能诊断

这是 `night-20261021-v3` 运行期间从源码与证据提炼的后续知识，不注入本批已冻结的 KG/HG-KDA 分析角色。修复候选的真机正确性和性能以各独立批次结果为准。

## 先建立语义与寻址模型

`value_selecting_reduction_backward` 把归约选中位置的梯度写回原形状，其余位置补零。将输出逻辑形状写为 `(outer, red, inner)`，则：

```text
out[o, r, i] = grad[o, i]，当 indices[o, i] == r
out[o, r, i] = 0，其他位置
```

每个 `(o, i)` 只选一个归约位置，不需要原子累加。融合清零与选中梯度写入时，仍须写满输出，不能只写非零位置。

逻辑形状能折叠为二维，不代表物理布局也能折叠。任意布局的输入地址需要按非归约维逐维累加 `coordinate * stride`；只有满足相邻维的连续关系时，才能用一个扁平索引乘固定 stride。`keepdim` 需要正确处理保留的单例维度；PyTorch 的 `is_contiguous()` 也不强制单例维的 stride 为1。

## 分块改写的两个独立条件

1. 地址合法：每次有效读写的坐标都在允许范围内，输入 stride 被正确解释。
2. 覆盖完整：全部 program 生成的有效写入坐标覆盖整个输出域；本算子的每个输出位置有唯一写入者。

mask 主要约束第一个条件，不能自动保证第二个条件。原生 profiler 第二轮使用向下取整的 `COLS=4` 处理长度5的归约维，又把 grid 改成只按行分块，导致最后一列没有任何写入者。`cols < red` 不会补出缺失的列。

可行改法包括向上取整并保留 mask、用额外列分块覆盖剩余位置，或只在可证明完整覆盖的形状域使用快路径。检查至少包含非2次幂、超过单块上限、空输入、单例维，以及三维以上的非仿射转置布局。

## 将性能证据对应到修改

| 观测与待区分机制 | 建议的补测 | 可能修改 |
|---|---|---|
| program 数增大时延迟增大：调度、重复标量读还是寻址开销？ | 固定工作量改变 grid；对照简单填充 kernel；检查每program处理量与实际流水记录 | 合并多行、persistent grid、减少重复地址计算 |
| 大输入增加字节数却没有等比例增加时长：是否受固定开销主导？ | 相同几何的dtype对照、独立设备任务计时，以及完整调用计时 | 分开优化 host 参数组织与设备 program 结构 |
| Scalar 活跃较高：循环、除法、依赖等待还是调度？ | 同候选指令与源码热点；无法采集时保留多个解释 | 编译期几何参数、化简索引、增大每program有效工作量 |
| 单kernel融合与“清零＋散射”两kernel各有优势 | 同合同测全部形状，同时核对初始化、输入布局和输出语义 | 按可证明的输入特征分流，保留通用路径 |

流水活跃比例不等于峰值利用率，各流水比例不能直接相加成总耗时。观察到的最高吞吐也不是硬件峰值。当前尚未建立定量 Roofline，报告不能用这些观测冒充上限模型。
