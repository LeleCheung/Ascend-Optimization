# 新25算子与成对机制诊断计划

目标：在固定FlagGems、FlagTree和KGS条件下，将导师新指定的25项完成接口核对、正确性修复和性能优化；简单算子用成对真机指标，复杂算子升级到热点区域与流水空泡分析，沉淀可复用经验。验收仍为完整正确且相对PyTorch超过0.8×；不同计时范围和参考条件分别报告。

## 执行顺序

1. 固定源码、合同、输入、软件版本及SHA；生成25项目标表。已有成果保留为可复用起点，重新建立同批数据，不改写历史成绩。
2. 现有HG-KDA立即开始简单和复杂代表项，再持续处理其余项目。新方法同步开发并在代表项接入；不等待25项全部优化停滞才使用新方法。
3. 新增Ascend C性能参考注册与核验：明确输入、dtype、布局、原地/out语义、stream、实际入口和二进制/源码身份。PyTorch继续承担正确性和历史成绩参考。候选默认继续Triton，不将“对照Ascend C”解释为全部候选改写为Ascend C。
4. 成对数据先经脚本形成含两边实测值、单位、绝对差、比率、缺失/零分母和统计范围的证据。按差异幅度筛选摘要，原始指标可追溯；Agent结合源码、实际IR和经验提出可验证修改。
5. 模拟器从单条指令扩展为源码邻域/执行阶段热点区域；真实trace有起止时间时，按核和流水求区间并集及空闲补集。缺时间轴明确不支持空泡计算；等待和空闲分开，不能用1减活跃比例代替。
6. 结构化知识记录适用算子、dtype/布局/编译器、证据SHA、成功与失败约束。自动去重、标记替代、限额检索；只有有完整评测证据的方法进入已验证库，历史原件保留。
7. 每项一次正式完整KGS评测，加原地/out、非连续、特殊值等针对性检查；保留同批最快有效源码、实际模型请求、失败和复现命令。三端同步另行记录，不在运行中更新共享服务或镜像。

## 参考与方法边界

- 当前固定FlagGems为d6a8eec473517a3d68157b208eb9c057eb1d4c50，FlagTree为0.6.0+ascend.gitc286cba6，CANN9.0.0。KG6.7.0/KGS6.5.0历史快照继续使用；未将上游dev/master不可访问写成已升级。
- CANN的aclnn入口是原生库参考；只有查明实现源码/构建产物后才标为Ascend C源码参考。自写弱参考不能代表厂商最优。
- Roofline用于粗分类及理论空间，复杂算子以成对profiling为主。经验峰值和厂商模型分别标注，不拿估计值代替实测。
- 单条指令时间排序、源码邻域聚合和有时间轴的区域/空泡分析分别标注。调试行号不自动等于性能根因；重叠指令时间不直接求和当真实耗时。
- 0.7/0.5活跃比例只是历史启发式；高活跃不必然是瓶颈，新结论须由指标变化和完整正确性验证。
