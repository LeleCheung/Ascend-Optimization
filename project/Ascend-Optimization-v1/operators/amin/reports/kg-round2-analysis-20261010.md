# amin 原生 KG 两组第二轮分析

截至 2026-10-10 23:42，两组第二轮都通过完整 27 项测试。无 profiler 为 **0.742×**，原生 profiler 为 **0.512×**；我们的 v5 完整评测为 **0.916×**。这些是阶段数据，最终四版本表使用另外保存的独立复验结果。

profiler 版没有优化到所有慢路径：1M 元素的全归约仍沿用 master 的两阶段小分块，三个 dtype 约 **40～44 μs**；无 profiler 版为 **14 μs**，我们的 v5 为 **6 μs**。4096×4096 的末轴归约，profiler 版约 **87～96 μs**，无 profiler 为 **43～62 μs**，v5 为 **39～60 μs**。这两类用例拖低了 profiler 版整体成绩。

两组都改善了中间轴归约，避免转置后复制整个输入。profiler 版在 float32 的 1024³ 中间轴用例约 **3.33 ms**，快于无 profiler 的 **4.54 ms**，接近 v5 的 **3.30 ms**。因此它的分析确实帮助了一部分用例，但最终选择的归约分块和未覆盖路径使整体结果更慢。

下一步继续改善 bf16 的循环类型和归约分块，保留完整通过的最快候选。性能范围是 FlagGems core 的设备 kernel 计时，15 个性能 case 取几何平均；上述差距不解释为 Python host 开销，也不代表已经测得物理 Roofline 上限。
