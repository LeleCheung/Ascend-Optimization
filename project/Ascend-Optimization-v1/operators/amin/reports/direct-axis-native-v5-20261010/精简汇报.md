# amin 阶段汇报

固定 FlagGems master 后，原版在大输入上超过 Ascend 启动数量上限，先做保留原内核与 autotune 的启动兼容修复。该基线相对 PyTorch 为 **0.296×**；我们的新版通过完整 **27/27** 测试，达到 **0.916×**，相对兼容基线提高 **3.11×**，超过本阶段 0.8× 目标。

关键优化是直接沿原布局归约，减少转置；根据真实设备计时调整多行、宽列分块；对应分支关闭多缓冲。仍最慢的 case 为 bfloat16 的 `[1024,1024,1024]` 中间轴归约，只有 **0.394×**，因此后续改善空间集中在大输入搬运与归约流水线。

数值是固定 KGS 合同下的 FlagGems core 设备 kernel 计时，15 个性能 case 的几何平均；另外 12 个为正确性 case。基线与新版的 PyTorch 参考延迟几何平均变化为 0.994×。KG 无 profiler、有原生 profiler 两组仍待完成，当前是优化候选阶段成果。

复现与逐 case 数据见 [版本对比](版本对比.md)、同名 CSV、`direct-axis-native-v5-1.request.json` 和 `direct-axis-native-v5.provenance.json`。源码为 `../../candidates/direct-axis-native-v5-20261010.py`，SHA-256：`599ede4d0d21c4e1c7fb2c5b26d2f7ab3518c6edcae46ca0491ee4abe0923eb7`。
