# 夜间连续优化交付

本轮连续执行六个算子的两批有限搜索、独立语义检查、一次正式完整 KGS 和最终采集。新增有效结果包括 `gelu_and_mul` **2.271×**、标准 Philox 修复后的 `uniform` **1.325×**、`rad2deg_` **1.117×**；`selu_` **0.837×**，同批真实加速 **1.042×**。`scatter_add` 正确性已修复但只有 **0.419×**；`cumulative_trapezoid` 尚无通过全部数值检查的交付。

固定 FlagGems `d6a8eec473517a3d68157b208eb9c057eb1d4c50`、FlagGems-SGLang `938612058a981487e439da514df7d1371cf31e68`、FlagTree `0.6.0+ascend.gitc286cba6`、CANN 9.0.0。全部采用 910B 物理卡 7、KGS 19659 的完整调用 walltime，相对 PyTorch 等价参考计分。性能表不混用历史设备 kernel 计时，也不将两组相对 PyTorch 分数相除当作优化收益。

## 有效知识与贡献

CC/DeepSeek 通过原生 KG 工具完成候选生成、真机探针、分块与启动方案搜索。Codex 提供已有机制知识、连续控制、独立门禁、选版审计与追加修复；不能把这些结果称为纯原生 KG 独立取得。

GELU 真机探针发现，在两组各 2²⁰ 个 FP32 样本上，本机 `F.gelu(approximate='none')` 与 `'tanh'` 逐位相同，接近 CPU 的 tanh 公式。匹配本机评测参考后，FP32 扩展检查通过；二维连续 tile 同时解决了原路径的索引和任务组织开销。这个结论限于本次固定软件栈和已测样本。

uniform 形成了具体的“设备反例→整数机制→修复→完整验收”闭环。独立原语探针发现无符号右移被执行为算术右移，`umulhi` 也偏离无符号参考；显式 signed shift＋掩码使标准 Philox 逐位检查通过。counter 的无符号比较又触发不支持的 `uint32→uint64` 转换，改用位运算进位后完整检查通过。详见[整数机制报告](../tools/profiling/hgkda/research/uniform无符号整数修复-20261023.md)。旧 **1.497×** 源码未通过标准 Philox 核验，保留证据，不作为最终交付。

本轮使用真实设备任务、编译 IR 与 PipeUtilization；没有建立定量 Roofline。失败／超时的模拟器请求不计为成功指令分析。

## 采集与剩余限制

GELU、scatter 和 uniform 的最终采集以各自原始回执为准。SELU、rad2deg_ 的额外采集兼容源码保持计算 kernel AST 不变，成对 trace／IR 成功，但 KGS msprof metrics 仍失败：`without profile completion marker`。这两项保留为明确采集缺口。

兼容源码独立正式结果为 SELU 0.862×、rad2deg_ 1.059×；它们是元数据／缓存修复后的独立评测，不用较高复测分数宣称新增性能收益。表格保留主批按实际延迟选中的版本。

累计积分保留全部失败：第二批三份候选虽然原 KGS 33/33，但扩展仅 16/18，全部性能输入数值仅 2/9、2/9、3/9。原 Native timing 阶段不验证输出，因此增加性能输入数值检查是必要的。
