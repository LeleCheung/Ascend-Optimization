累计积分的FP32累加提案已完成本轮真实评测：正式33/33、相对PyTorch0.880×，但fresh输入/stream补测仍34/36，未计达标。单独提高累加精度不足以解决这次补测失败。历史固定反例已经说明：一个确定性候选未必能同时满足默认参考的全部漂移结果，数学更精确也不能直接推导为逐值合同通过。正式失败和补测失败分别保留。

随后KG第四轮的预绑定启动原稿正式得到2.177×，但缓存遗漏stride与device，已按源码SHA人工拒绝。Codex修复缓存后的源码正式33/33、相对PyTorch2.147×，补测32/36。进一步恢复BF16增量舍入与FP32扫描、统一FP32 scratch的`codex-plan-precision-v2`已实测：正式33/33、相对PyTorch2.074×，补测34/36；BF16两项失败消失，FP16非末轴两组fresh输入仍失败。以上成绩均相对原PyTorch，不是相对CANN达标。

求逆的离线历史在每个矩阵上检查24种布局、倒数／除法、LU与求解融合等组合；正常矩阵均能匹配，三个奇异矩阵没有匹配。这个结果是排除重复尝试的线索，不是“所有Triton算法都不可能”的证明。本轮搜索只接受通用算法，不按固定输入预存结果。

继续检查PyTorch 2.9.0与OpenBLAS 0.3.30官方源码后，新增了此前未覆盖的按列延迟更新顺序：当前列先执行旧置换，再算上三角的点积，下半列逐项FMA更新，最后选主元并用倒数缩放。转置分解后依次求解U的转置、L的转置并执行逆置换。在768组离线运算顺序检查中，存在共同配置匹配全部三个冻结奇异矩阵。Linux Python 3.11复放的info和LU对角线与Windows记录一致；这只是源码引导的数值假设，尚非NPU正确性或性能结果，也没有解决CANN完整参考缺口。源码、输入身份及逐组结果见`analysis/linalg_inv_ex/leftlooking-summary-v1.json`。

Codex的`codex-leftlooking-v1`已完成运行时准入：0/5，原因是小矩阵的编译转换失败及大矩阵输入／输出地址同名导致循环变量形状冲突，并非已完成数值评测。KG第一轮三份候选分别为5/7、3/7、5/7，原40分钟搜索已终态。

独立算术诊断在2048个样本上发现显式FMA与CPU `fmaf`的差异；扩展到8192个普通指数范围／消去样本后，两个融合开关下FMA均有4588项不同，普通商／倒数有451／546项不同。补偿乘加、余数修正商／倒数均为0项不同。实际TTIR仍含`math.fma`，adapter将`tt.precise_divf`转为`arith.divf`；两种融合开关的npubin字节相同。结果定位了当前环境的算术差异，仍需完整求逆验证。

`codex-compensated-lu-v2`继承大矩阵地址变量错误，已在未执行设备测量前人工拒绝。v3离线编译发现constexpr反向索引错误；v4修正后3×3可编译，但7×7静态展开超出单CPU的300秒预算。动态循环v5已完成离线编译4/4、运行时5/5，正式3/7；小矩阵4项仍失败，大矩阵3项通过。原函数体CPU逐句模型4/4，后续通过LU／三角求解阶段与标量/向量混合算术诊断继续定位；另一份按列求解v6也通过CPU模型4/4并排队等待NPU。源码、诊断与角色注入证据见[求逆与扫描接续记录](阶段记录-求逆舍入与扫描修正.md)。
