# 剩余算子的原生参考入口复核

本轮继续查找CANN 9.0同版本的可用入口，不修改冻结输入、容差、确定性模式或已有参考。清点是CPU只读操作，探测单独进入卡7串行队列；不把接口存在当作已达标。

| 对象 | 新发现 | 当前结论 |
| --- | --- | --- |
| expm1_ | aclnnForeachExpm1及GetWorkspaceSize头文件和导出存在；单张量list适配完成构建及卡7串行数值探测 | 三种dtype、是否别名输出及是否非连续，共12项，0/12通过；未获得新合格参考，未做正式性能评测 |
| fractional_max_pool3d | 旧ACL图接口有FractionalMaxPool，但声明为4-D NHWC，输出row/col pooling sequence，且声明走AICPU | 不是当前3D池化的5-D输入、外部random_samples及argmax接口，不能替代本算子参考 |
| linalg_inv_ex | 旧ACL有Lu、MatrixInverse；Lu输出lu及行排列p，未提供inv_ex的inverse＋info接口；搜索的专用aclnnInvEx/LuFactorEx符号未发现 | 不能把单独inverse接口当完整inv_ex，不伪造info；现有奇异输入逐值合同问题继续保留 |

ForeachExpm1适配的C++只属于参考侧。它调用原生CANN目标接口，并复用官方tensor-list元数据转换和释放；不通过PyTorch目标算子计算，也没有进入任何HG-KDA候选。实际探测仍出现小值消去误差：连续FP32输入约`1e-8`时原生输出为`0`，CPU数学参考约为`1e-8`；输入`-0`时输出为`+0`。非连续输入与输出别名组合还出现原NPU一致性检查失败。完整向量与每项失败原因保留于`reference-probes/native-foreach-expm1-v1/numerics.json`。这些是已测试路径的反例，不据此断言所有CANN版本或所有输入都失败。

可复核原件：`reference-probes/cann-9-interface-inventory-v1.json`、`reference-probes/native-foreach-expm1-v1/build.json`及`numerics.json`。探测没有修改输入、容差或参考，也没有计入CANN达标数。
