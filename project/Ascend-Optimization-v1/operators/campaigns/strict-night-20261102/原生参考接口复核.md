# 剩余算子的原生参考入口复核

本轮继续查找CANN 9.0同版本的可用入口，不修改冻结输入、容差、确定性模式或已有参考。清点是CPU只读操作，探测单独进入卡7串行队列；不把接口存在当作已达标。

| 对象 | 新发现 | 当前结论 |
| --- | --- | --- |
| expm1_ | aclnnForeachExpm1及GetWorkspaceSize头文件和导出存在；单张量list适配已单CPU构建并绑定源码、二进制、官方元数据转换头文件SHA | 作为另一条原生CANN路径，下一空闲点测试原有小值/零符号门槛；未做正式性能评测 |
| fractional_max_pool3d | 旧ACL图接口有FractionalMaxPool，但声明为4-D NHWC，输出row/col pooling sequence，且声明走AICPU | 不是当前3D池化的5-D输入、外部random_samples及argmax接口，不能替代本算子参考 |
| linalg_inv_ex | 旧ACL有Lu、MatrixInverse；Lu输出lu及行排列p，未提供inv_ex的inverse＋info接口；搜索的专用aclnnInvEx/LuFactorEx符号未发现 | 不能把单独inverse接口当完整inv_ex，不伪造info；现有奇异输入逐值合同问题继续保留 |

ForeachExpm1适配的C++只属于参考侧。它调用原生CANN目标接口，并复用官方tensor-list元数据转换和释放；不通过PyTorch目标算子计算，也没有进入任何HG-KDA候选。探测若通过，仍须完整合同、补测和实际设备路径核验，才讨论新参考资格；若失败则保留具体反例。

可复核原件：`reference-probes/cann-9-interface-inventory-v1.json`及`reference-probes/native-foreach-expm1-v1/build.json`。原生库头文件中的“精度更高”描述与实测是否一致，最终以相同门槛的真机输出判断，不仅依赖手册。
