# 910B Roofline 校准与优化闭环

## 目标

复用导师提供的通用 Roofline 分析器，为 HG-KDA 增加有来源、有单位且采集范围一致的性能上限分析，并以矩阵乘完成优化验证。独立保存本批材料，不改写历史实验。

## 已完成结果

[最终中文报告](最终报告.md)包含计数来源、同输入矩阵对照、真实修改和完整评测。父版／候选各42/42正式评测与18/18补充检查；本批相对PyTorch分别0.862×、0.768×，同case候选相对父版仅0.888×，因此保留父版。不能把本轮写成新算子性能突破。

12项数值证据见 analysis-final/；中文图表在 analysis-final/中文图表/。已提取导师原分析器，确认CSV固定8192计数不能统一乘128。GM参考使用同PMU模型persistent copy，FP16／BF16／FP32计算参考分开；物理HBM峰值匹配仍未决。

final-roofline-summary.json可通过build-kg-overlay.py的--roofline-evidence注入KG分析角色。agent-review两批保留真实CC＋DeepSeek调用；角色消费验证与完整KG自主搜索分别说明。计时原CSV、编译失败、早期口径错误及模型错误推断全部保留。

复现命令见最终报告和[模块说明](../../../tools/profiling/hgkda/roofline/README.md)。本轮不commit／push；控制端与910B按逐文件SHA同步，GitHub保持原提交。

## 执行顺序

1. 核查历史 FOP 与 `2MNK` 的 128 倍差异：逐行计数、Cube/Vector 分类、采集范围和固定版本公式。
2. 以受控输入真机验证计数及时间，核对 GM/L2 接口流量与物理 HBM 流量，保留缺失状态。
3. 固定计算路径、精度和设备，测量经验吞吐及带宽参考；标称上限、经验参考和计数器推导值分别登记。
4. 从导师 Markdown 提取原分析代码并保存来源 SHA；适配本批 manifest、points 和诊断输入，形成中文图表。
5. 比较矩阵乘父版、候选和 PyTorch，结合源码/IR提出修改，经补充正确性和一次 KGS 完整正式评测决定是否采用。
6. 独立核验单位、公式、附件身份、逐 case 延迟和复现入口，输出简报与完整证据。

## 约束

- 使用项目卡7互斥锁、专用目录与 tmux，不改变共享镜像、服务或他人进程。
- 不把逻辑请求量当作物理 HBM 字节，不把活跃比例当作 Roofline 利用率。
- 实测吞吐参考不称为芯片理论峰值；尚不能标定的屋顶明确标记，不补零或外推。
- 同输入不同采集过程的计数与耗时须注明来源，无法核对执行范围时不合成为有效点。
- 原始证据、失败候选及计数口径保留；本轮不提交或推送 GitHub。
