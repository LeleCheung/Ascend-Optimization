# 排序归约的另一候选：分段扫描

同目录scatter-sort-prototype.py使用全行FP32前缀和，再对目标段取前缀差。CPU24组通过不代表所有数值分布安全：两个较大的前缀相减可能放大相消误差。

本机只读源码证明`tl.associative_scan`支持tuple输入和自定义`@triton.jit` combine，可探索排序后按key分段扫描：对于左段的`(sum_a,key_a)`与右段`(sum_b,key_b)`，返回`(where(key_a == key_b, sum_a + sum_b, sum_b), key_b)`。排序后的相同key连续，该结合算子应在CPU模型先验证；扫描末元素给出该目标key的归约结果。每个目标仅由段尾写一次，将原inp加上段和，未出现目标保留原inp。保持输出完整初始化，计时包含所有kernel与临时存储。

这可能避免跨目标的前缀相减；代价是tuple scan后端支持、UB和排序开销仍待验证。若用动态位置scatter写回，需测本机是否再次逐lane标量化；不能只看算法复杂度就认定快。也可以先写键/段和的连续临时buffer，第二kernel连续gather构造输出。优先利用已提供原型做正常preflight和debug，不盲目推翻已有效0.419×起点。

以上是Codex提出的未验证算法备选，不是已有设备成果，也不意味着应当把多个路线全部做完才交付。
