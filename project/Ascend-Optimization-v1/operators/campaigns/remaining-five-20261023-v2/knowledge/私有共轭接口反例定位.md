# _conj_physical：参考有效，原版复制回退失效

本批原版正式12/14，补充独立29/34。Codex在控制器暂停、在途操作结束且全部服务健康空闲后，用物理卡7逐阶段隔离，原始证据为research/_conj_physical/transfer-probe.json：

- lazy conjugate输入直接detach().cpu().clone成功，值与CPU逻辑输入一致，因此不是检查器传输误拒。
- 同一输入`torch.ops.aten._conj_physical`成功，返回NPU张量，因此不是参考就绪失败。
- 原固定候选失败：`_resolved`调用FlagGems `copy_`，复杂dtype走`CompositeExplicitAutograd` redispatch，最后报CPU backend没有`aten::_copy_from`。正式correctness-4/6同样失败。
- 实数FP16/BF16 stride2补充用例输出全错；需修真实stride读取，不能沿用该copy helper。

修复路线：输入的conj bit仅改变逻辑解释。设原存储z；bit为false时目标输出conj(z)，bit为true时目标输出z。因此先用metadata操作`raw = input.conj() if input.is_conj() else input`去掉lazy bit，读取raw实部/虚部时`NEGATE_IMAG = not input.is_conj()`。这不调用原始算子，也不需要resolve到临时Tensor。对真实底层pair用Triton读取并输出；保持当前stream、真实stride、独立分配和输出layout规则。实数实现独立stride-aware复制，不能直接返回输入。

对转置/offset/stride2，应按实际input、output stride寻址；complex view_as_real是metadata接口，但需确认raw已不带conj bit。输出不能保留lazy bit，也不能复用输入存储。原候选、失败和诊断探针保持原样。

正式性能分开列实数与complex64三项的几何平均；复杂输入的参考是否有CPU回退要查对应trace，不能用实数trace代表复数路径。以上是Codex追加机制诊断，CC/DeepSeek负责本轮生成与实测。
