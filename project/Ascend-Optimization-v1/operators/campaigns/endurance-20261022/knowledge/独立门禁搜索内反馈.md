# 独立门禁搜索内反馈

本知识在累计积分第二批角色冻结之后发布，只供后续新建覆盖层读取，不追改正在运行的角色。

前一批累计积分、scatter_add、uniform、GELU 出现过正式合同通过但扩展语义失败。性能计时输入也必须核对数值；高分不能覆盖错误结果。推荐在生成候选后、正式评测前，用原生调试接口检查当前源码；失败先修复，不把不合格候选当作优化成果。

在当前 KG 工作区执行以下文件打包命令，按本轮实际算子、源码路径替换参数，并使用全新 tmp 子目录：

```bash
python /data/hanle/ascend-optimization/Ascend-Optimization/project/Ascend-Optimization-v1/tools/profiling/hgkda/stage-endurance-check.py \
  --batch-dir /data/hanle/ascend-optimization/Ascend-Optimization/project/Ascend-Optimization-v1/operators/campaigns/endurance-20261022 \
  --workspace "$PWD" --source tmp/main.py \
  --operator scatter_add --output tmp/independent-check-r2
```

上述 Bash 只复制文件，不运行 NPU、不改正式合同、不占另一张卡。将 stdout 中 `debug_request` 对象传入当前原生 `mcp__kernelgen__submit_debug_job`，再通过原生工具等待任务完成并读取 `artifacts/independent-<源码SHA前12位>.json`。不要在宿主或另一个进程直接运行候选。这里沿用当前 KG/KGS 调试任务的串行设备路径。

打包时核对本批登记的检查器 SHA 和 definition/oracle/correctness/timing 四份合同 SHA；拒绝被修改的合同。检查回执必须对应本轮源码 SHA；修改任何源码字节后都应重新打包、重新检查。目录已存在时换新名字，不覆盖旧证据。

对累计积分要特别读取冻结性能输入的低精度数值结果；scatter_add 检查重复索引和非连续布局；uniform 检查真实 generator 推进、恢复重放以及 seed/offset 高位；GELU 检查 FP32 参考公式差异，不能只看 BF16 正式计时输入。SELU 仍使用既有三项专用检查，不支持本入口。

本工具是搜索内提前反馈，不代替控制器最终补充语义门禁和一次完整 KGS 正式评测。保存调试请求、原始回执、源码 SHA 和修复记录。只有实际调用且收到对应回执，才可报告本轮采用了这项反馈。
