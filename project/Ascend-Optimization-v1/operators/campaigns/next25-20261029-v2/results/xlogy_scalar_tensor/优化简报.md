# xlogy_scalar_tensor：融合计算与启动缓存修复

本批相对PyTorch完整调用加速比 **1.253×**，完整KGS **30/30**，补充检查 **72/72**。代表输入的PyTorch路径已观察到NPU执行。固定FlagGems原版为0.148×；历史设备计时结果不与本批混用。

## 算子与修改

算子对张量逐元素计算“标量乘以张量的自然对数”。标量为零时输出零，但张量中的NaN仍须保留；输出新分配，输入保持不变。

CC/DeepSeek生成了融合对数与乘法的Triton实现，并缓存编译结果和启动元数据，减少反复经过Python启动层的开销。连续输入按块处理；非连续输入按真实stride寻址。

Codex新增的连续标量切换补测发现，第二轮候选把第一次的标量保留在启动闭包中。其独立KGS为1.235×、30/30，但补测仅63/72；同一存储从标量2切换为-3、Inf或NaN时，连续路径仍使用旧值。

修订版保留三个计算kernel的AST，只让缓存的启动函数每次接收本次标量；grid、编译产物和常量仍可缓存。简化示例如下：

```python
# 旧方式：函数创建时保存了s，后续调用不接收新值。
def fast(y, out, saved_scalar=s):
    launch(..., saved_scalar, ...)

# 新方式：每次显式传入当前标量。
def fast(y, out, scalar):
    launch(..., scalar, ...)

entry(y, out, s)
```

这是KG/HG-KDA与Codex共同完成的优化和修复。不是纯原生KG独立结果，也不是新增对数算法。
