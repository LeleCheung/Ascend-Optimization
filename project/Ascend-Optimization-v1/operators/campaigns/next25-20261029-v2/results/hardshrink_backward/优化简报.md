# hardshrink_backward：目标参考语义与非连续路径修复

本批相对PyTorch完整调用加速比 **0.868×**，完整KGS **30/30**，补充检查 **45/45**，超过0.8×验收线。固定FlagGems原版实测为0.154×；代表输入已观察到PyTorch使用NPU路径。

这个算子计算Hardshrink的输入梯度：通常在输入落入阈值区间时抑制梯度，区间外保留传入梯度。本机NPU参考在被抑制的梯度为Inf时输出NaN，CPU参考输出零；本项目按冻结的目标NPU合同对齐，保留两侧原始向量。

CC/DeepSeek生成连续输入的融合计算、分块和缓存启动。Codex根据补测，将直接选择零的写法改为FP32梯度乘掩码，保留目标NPU的非有限值行为，并避免BF16常量转换的编译问题。

随后两个版本在非连续路径报Vector异常。厂商日志均明确指向`_hsb_scaled_0`的UB地址越界。修订版在这条路径先取得连续输入，再调用连续kernel；正式计时的连续输入仍采用缓存启动。最终完整评测与45项补测均通过。日志定位到了故障kernel和地址类型，具体编译变换仍待进一步定位。
