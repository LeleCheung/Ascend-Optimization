## 数值与接口

语义为`log2(2**x + 2**y)`。上游稳定公式是`max(x,y) + log2(1 + exp2(-abs(x-y)))`，中间值使用FP32。直接计算`2**x + 2**y`有溢出风险。

相同无穷大使`x-y`为NaN，此时结果应恢复为`max(x,y)`；真实NaN输入仍须传播NaN。保持广播、stride、输出dtype和类型提升，不用同dtype连续输入的优化破坏通用回退。FP16/BF16下减少中间精度可能引入消减误差，不能仅凭随机值精度通过就假设安全。

固定测试包含常规形状及非有限值；独立完整合同为36项。测试范围来自KGS inspect，不能删减、特判测试输入或从benchmark名称选实现。按公开shape/dtype/stride选择实现是正常优化。

## 优化方向

1. 先按正式逐case延迟和真机流水指标选择方向。Vector比例高时检查exp/log、转换与临时向量；MTE2比例高时检查连续搬运和分块；Scalar比例高时检查动态广播索引与program覆盖。流水指标之间可重叠，不能相加，也不等于峰值利用率。
2. 连续同形输入可绕过`pointwise_dynamic`的通用地址计算，但保留广播、非连续及类型提升回退。一个program处理多块可以减少控制开销，也会降低并行度；避免相邻尺寸从大量program骤降到一个program，尤其不能把FP16慢case隐藏在整体几何均值中。
3. exp/log通常产生多个FP32临时向量，增大BLOCK需要考虑UB压力。融合表达式、减少存活向量、改变块大小或每program循环次数后，都须记录完整正确性和全部性能case。
4. 数值等价的`log1p(exp2(-abs(x-y))) / ln(2)`可作为备选，但不保证更快。固定参考代码的`third_party/ascend/language/cann/libdevice.py`定义`log1p`，其支持类型随路径变化；引用之前核实当前安装的API和可编译性。不能凭参考文件存在便假定当前后端支持，也不把它当作已验证改进。
5. 若尝试近似exp/log或较低精度，明确误差来源并保持NaN/Inf语义，使用完整合同复验；不修改容差、不调用PyTorch原算子替代，不静默吞掉运行错误。优先采用本机可编译且正确的公式和分块改进。

数值Roofline需要真实物理字节、相应指令工作量、设备范围和可信roof；exp/log不能简单算成一条普通FLOP。当前使用实际流水和延迟指导候选，不声称已达到硬件上限。

"""logaddexp2：保留通用广播回退；连续同形输入走无掩码、带流水循环的 AIV 向量核。

相对上一版最佳候选的三处改动（仅限连续同形快速路径）：
1) grid 收敛：大 shape 不再“每 program 只跑 1 个 tile”，让每个 program 有 4~8 次循环迭代；
2) n 整除 BLOCK 时走 EVEN 常量分支，逐 tile 去掉掩码比较与谓词访存；
3) 数值公式改用基底 2 内建 exp2/log2，去掉两次显式缩放乘法，缩短 FP32 临时量存活区间。

非连续 / 广播 / 类型提升 / 非整除尾块仍走原通用路径与带掩码分支，语义不变。
"""
import torch
import triton
import triton.language as tl
from flag_gems.utils import pointwise_dynamic


@pointwise_dynamic(is_tensor=[True, True], promotion_methods=[(0, 1, "DEFAULT")])
@triton.jit
def logaddexp2_general(x, y):
    xf = x.to(tl.float32)
    yf = y.to(tl.float32)
    m = tl.maximum(xf, yf)
    d = xf - yf
    r = m + tl.log2(1.0 + tl.exp2(-tl.abs(d)))
    r = tl.where(d != d, m, r)
    return tl.where((xf != xf) | (yf != yf), float("nan"), r)


@triton.jit
def logaddexp2_bounded_kernel(X, Y, O, n, BLOCK: tl.constexpr, EVEN: tl.constexpr):
    start = tl.program_id(0) * BLOCK
    step = tl.num_programs(0) * BLOCK
    for base in tl.range(start, n, step):
        offsets = base + tl.arange(0, BLOCK)
        if EVEN:
            xf = tl.load(X + offsets).to(tl.float32)
            yf = tl.load(Y + offsets).to(tl.float32)
        else:
            mask = offsets < n
            xf = tl.load(X + offsets, mask=mask, other=0.0).to(tl.float32)
            yf = tl.load(Y + offsets, mask=mask, other=0.0).to(tl.float32)
        m = tl.maximum(xf, yf)
        d = xf - yf
        r = m + tl.log2(1.0 + tl.exp2(-tl.abs(d)))
        r = tl.where(d != d, m, r)
        r = tl.where((xf != xf) | (yf != yf), float("nan"), r)
        rc = r.to(O.dtype.element_ty)
        if EVEN:
            tl.store(O + offsets, rc)
        else:
            tl.store(O + offsets, rc, mask=mask)


def run(self, other):
    if (isinstance(self, torch.Tensor) and isinstance(other, torch.Tensor)
            and self.dtype == other.dtype and self.dtype in (torch.float16, torch.bfloat16, torch.float32)
            and self.shape == other.shape and self.device == other.device
            and self.is_contiguous() and other.is_contiguous()
            and self.numel() < (1 << 31)):
        out = torch.empty_like(self)
        n = self.numel()
        if n:
            if n <= 65536:
                block = 256
                grid = triton.cdiv(n, block)
            else:
                block = 4096
                tiles = triton.cdiv(n, block)
                # 至少保留 1024 个 program（并行度）并封顶 4096；
                # 大 shape 让每个 program 迭代 4~8 次以复用循环流水，
                # 与 1G case 已经体现出的更优“每元素耗时”保持一致。
                grid = min(tiles, 4096, max(1024, tiles // 8))
            logaddexp2_bounded_kernel[(grid,)](
                self, other, out, n, BLOCK=block, EVEN=(n % block == 0))
        return out
    return logaddexp2_general(self, other)
