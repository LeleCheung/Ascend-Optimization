# HG-KDA 下一阶段目标与验收

会议后的主线是：固定基线，覆盖简单和复杂算子，将已有经验发展为可插入 KG 的分阶段体检方法，评测继续使用 KGS。上一阶段四算子的原始证据保留，不作为本阶段重新生成的成果。

## 固定版本

FlagGems 固定 `d6a8eec473517a3d68157b208eb9c057eb1d4c50`，FlagTree 固定 `0.6.0+ascend.gitc286cba6`，保留现有镜像与 CANN 9.0.0。FlagGems-sglang 选型固定 `938612058a981487e439da514df7d1371cf31e68`，另建评测合同，不假定现有 FlagGems adapter 能直接运行。

身份与核验入口见[锁定文件](../../../manifests/hgkda-stage2.lock.json)和[HG-KDA 接入](../tools/profiling/hgkda/README.md)。同一算子各组必须使用相同版本、合同和预算；如需要评估新 FlagTree/TLE Raw，单独设组。

## 分阶段体检

1. 核对版本、源码与合同，复测正确性与逐 case 性能。
2. 简单算子先采集真机指标。结合算子特征提出可验证假设，路由到对应知识。
3. 复杂算子及多流水难以解释的情况，追加模拟器指令、同步与热点分析。一次只升级代表用例，保留原始附件与对应源码身份。
4. 模型生成具体改法，KGS 完整测试，自动保留最佳并最终复验两次。移除边界掩码的候选保留专家评审项，评测通过不替代评审。
5. 将新证据和失败经验补回按“算子类型＋性能指标”组织的知识库。

## DMA 与 TLE Raw

历史 narrow_copy 的有效快路径直接绑定 `libacl_rt.so` 的 `aclrtMemcpyAsync`，PyTorch 用于张量分配、地址和当前 stream；同时保留的回退路径需单独审查，不能把“源码有回退”当作实测一定命中回退。

[FlagTree PR #1238](https://github.com/flagos-ai/FlagTree/pull/1238) 在本次查阅时未合并，固定 head 为 `163a6f69ae36c14e2a4dd342062078542ed3158d`。它提供 kernel 内的 AscendC 自定义操作接入与 `tle_raw.call` 入口，不能直接当作宿主侧 `aclrtMemcpyAsync` 的同义包装。当前安装版本没有该 PR 的统一 `language.raw` 接口；先记录能力，再决定独立编译器组的最小验证，不升级现有对照环境。

## 本 goal 的交付标准

- 可核验的基线锁定与 15 项登记。
- 可插入 KG 分析角色的项目内 skill/覆盖层，以及继续使用 KGS 的控制器入口。
- 分类知识、阶段选择和指令热点筛选的可执行实现与验证。
- 当前 DMA 调用链与 TLE Raw 能力的实际核查记录。
- 至少一个新算子的真机完整正确性、候选迭代和两次最终复验，报告起点、改法、成绩与失败情况。其余对象以真实状态列入队列，不把未测写成完成。
