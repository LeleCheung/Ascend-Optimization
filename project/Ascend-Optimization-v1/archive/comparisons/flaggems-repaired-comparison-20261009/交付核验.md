# 本轮交付核验

本轮目标是修复三项历史 FlagGems 在现有 KGS 合同下的正确性问题，并与候选完成同卡、同 workload 三轮对照。最终成果为历史方法验证，不代替 Excel 华为列低于 0.8× 的后续主线。

| 目标要求 | 当前证据 |
|---|---|
| 三项正确性修复与接口适配分别记录 | [总报告修复表](README.md)、[原版/修复版/补丁/SHA](validated-v5/repairs/)、[历史测试合同差异](../flaggems-comparison-20261009/measurements/contracts/) |
| 双方相同完整 workload | [protocol.json](validated-v5/protocol.json) 定义 PReLU 21+9、BatchNorm 30+15、SmoothL1 291+12；汇总器逐项验证 UUID、phase、axes、完整状态及通过数 |
| 同一张 910B 与三轮串行对照 | [experiment.json](validated-v5/measurements/experiment.json) 记录物理 NPU 7、三轮和交替先后顺序；[执行快照](executed-scripts/)与[最终 PReLU 批次](followup-prelu-accurate/)记录单卡服务与原日志 |
| 双方每轮完整通过 | [最终 measurements](validated-v5/measurements/)包含三项共 18 份请求和结果；audit 从原始结果重算汇总，任一用例失败则拒绝性能结论 |
| 逐 case 实际延迟与直接几何平均比 | [per-case.csv](validated-v5/per-case.csv) 共 108 行，每行含基线/候选及双方 PyTorch 延迟；[comparison.json](validated-v5/comparison.json)给出三轮直接比、中位数和范围 |
| 可用于周报的中文报告 | [周报精简版](周报精简版.md)，列出 1.97×、2.19×、1.61× 以及 PReLU 新候选相对 PyTorch 为 0.95× 的事实 |
| 保留原版失败与历次证据 | [历史联合报告](../flaggems-comparison-20261009/README.md)、[PReLU 精度诊断](diagnostics/README.md)、v1–v5 原请求及源码独立归档；原始结果未被最终汇总覆盖 |
| 明确基线为修复版 | 总报告、周报和最终报告均说明原版本提交及本机修复；PReLU 新增补偿归约耗时计入基线 |
| 复现源码并保护共享环境 | [delivery-audit.json](validated-v5/delivery-audit.json)记录重建代码在换行归一化后一致，实际请求 SHA 严格按原字节匹配；[environment-current.json](environment-current.json)记录共享原文件/HEAD 未变，五个本次专用服务均已退出 |
