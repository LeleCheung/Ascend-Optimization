1. 准备 triton 算子

```Python
import torch
import torch_npu
import triton
import triton.language as tl

@triton.jit
def add_kernel(
    output_ptr,
    x_ptr,
    y_ptr,
    n_elements,
    BLOCK_SIZE: tl.constexpr,
):
    pid = tl.program_id(0)
    offsets = pid * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE)
    mask = offsets < n_elements

    x = tl.load(x_ptr + offsets, mask=mask)
    y = tl.load(y_ptr + offsets, mask=mask)

    tl.store(output_ptr + offsets, x + y, mask=mask)

M = 1024
N = 1024

x = torch.randn((M, N), dtype=torch.float32, device="npu")
y = torch.randn((M, N), dtype=torch.float32, device="npu")
out = torch.empty_like(x)

n_elements = x.numel()

BLOCK_SIZE = 256
grid = (triton.cdiv(n_elements, BLOCK_SIZE),)

# 真正希望 profile 的 launch
add_kernel[grid](
    out,
    x,
    y,
    n_elements,
    BLOCK_SIZE=BLOCK_SIZE,
)

torch.npu.synchronize()
```

### 上板采集

https://gitcode\.com/Ascend/msopprof/blob/master/docs/zh/user\_guide/msopprof\_user\_guide\.md

```Bash
msopprof --application="python3 test_add.py" \
  --output=./output_dir
```

输出：

```SQL
output_dir/
└── OPPROF_20260817083525_FJZSHPVWHRZGALHO
    ├── ArithmeticUtilization.csv
    ├── L2Cache.csv
    ├── Memory.csv
    ├── MemoryL0.csv
    ├── MemoryUB.csv
    ├── OpBasicInfo.csv
    ├── PipeUtilization.csv
    ├── ResourceConflictRatio.csv
    ├── dump/
    └── visualize_data.bin
```

除了 OpBasicInfo 是算子级汇总外，其余 7 个 CSV 都是每个 AI Core block 一行（4096 行），分别刻画执行单元、访存、缓存、冲突的不同侧面。字段前缀约定：aic\_\* = AI Cube 单元（矩阵计算），aiv\_\* = AI Vector 单元（向量计算）。

各文件含义

- `OpBasicInfo.csv` — 算子基本信息：名称、类型（vector/cube/mix）、总耗时、block 数、频率。一行一个算子。

- `PipeUtilization.csv` — 各执行流水线占用率（核心文件）：

    - \*\_vec\_time/ratio：向量单元执行时间/占比

    - \*\_mte1/2/3\_\*：MTE 搬运引擎（mte1=加载到 L1、mte2=GM↔UB 搬入、mte3=UB→GM 写回）的时间和占比，及对应带宽

    - \*\_scalar\_\*：标量单元执行时间，以及 scalar 等待各单元的 stall 时间（scalar\_mte2\_stall 等 = 因等搬运而停顿）

    - icache\_miss\_rate：指令缓存 miss 率

- `ArithmeticUtilization.csv` — 算术单元利用率：cube/vector

单元的指令占比，按数据类型细分（fp16/fp32/int8/int32/misc），fops = 浮点操作数。用来判断算力是否用满。

- `Memory.csv` — 主存/L1 访存带宽与数据量：main\_mem\_read/write\_bw（GB/s）、MTE 指令数与占比，以及

GM↔L1、L0C、UB 各层级的搬运数据量（KB）和带宽利用率（\*\_bw\_usage\_rate）。这是判断 memory\-bound

的关键文件。

- `MemoryL0.csv` — L0 缓冲带宽：L0A/L0B（cube 输入）、L0C（cube 输出/累加器）的读写带宽。

- `MemoryUB.csv` — UB（Unified Buffer）带宽：vector 单元和 scalar 单元对 UB 的读写带宽。

- `L2Cache.csv` — L2 缓存命中率：各 block 的读/写 hit、miss\-allocate 次数和命中率（%）。

- `ResourceConflictRatio.csv` — 资源冲突/等待比：cube、mte 的等待占比；vector 的 bankgroup\_cflt/bank\_cflt（UB bank 冲突）、resc\_cflt（资源冲突）、vec\_mte\_cflt（向量与搬运抢资源）等。

### 仿真采集

https://gitcode\.com/Ascend/msopprof/blob/master/docs/zh/user\_guide/msopprof\_simulator\_user\_guide\.md

```Bash
msopprof simulator --soc-version=Ascendxxxyy \
  --application="python3 test_add.py" \
  --output=./output_dir
```

参数 `--soc-version` 的值可通过执行以下命令获取：`python3 -c "import acl; print(acl.get_soc_name())"`，可通过 `ls $ASCEND_HOME_PATH/tools/simulator` 查对应的名称


输出：

```Bash
output_dir/OPPROF_20260817083925_ESOXENAHYBNHTGOP/
├── dump
│   ├── aicore_binary.o
│   ├── object_dump.txt
│   └── pc_start_addr.txt
└── simulator
    ├── core[x].veccore[y] # 每个 core 
    ├── trace.json
    └── visualize_data.bin
```
