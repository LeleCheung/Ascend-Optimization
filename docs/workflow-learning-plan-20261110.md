# 从历史优化成果到可复用工作流：实验计划与文献定位

日期：2026-11-10。本文是后续目标建议及相关文献快速调研，不表示已启动新设备实验。实现分工遵循[最高决策](../AGENTS.md#最高决策诊断与候选实现分工)。

## 当前起点与研究问题

当前原合同及语义口径达标26/30，主要证明已有候选的性能与正确性。独立CLI复测已有源码、CC／DeepSeek结合Codex指导生成新源码，以及冻结skill后独立完成优化，是不同的验证对象。

SELU新生成版经方法指导由0.210037×提高到0.887010× CANN，历史源码独立回归为1.039292×。恢复中暴露的核心问题是历史方法检索缺失、代表输入选择不充分，以及正式性能结果未驱动持续修改。该结果支持进一步研究：能否将Codex的诊断经验转化为可检索知识和可执行工作流，使CC／DeepSeek在其他算子上复用。

## 分阶段目标

| 阶段 | 对象 | 需要交付的结论 |
| --- | --- | --- |
| 再验证一个 | 建议`log10_`，当前已有候选相对CANN为0.940911×，正式36项 | 遵循新分工，从固定起点经方法检索、候选生成、完整评测及性能反馈得到严格Triton达标版；所有候选修改由CC／DeepSeek完成 |
| 五个代表 | 建议`selu_`、`log10_`、`uniform`、`value_selecting_reduction_backward`、`native_group_norm`，包含前述试点 | 覆盖逐元素、随机状态、索引回填和归约；确认公共调度能工作，并记录哪些专项方法仍需补齐 |
| 全量覆盖 | 先覆盖26个已有达标的主线算子，再处理其余4项 | 逐算子报告生成结果、正确性、补测、相对CANN性能与成本；无法完成或未达标的如实保留 |
| 两版本汇总 | 历史最佳严格Triton版与新工作流生成版 | 在一致参考、合同、精度、计时及实现约束下比较；每个算子从第一阶段起就保存两条记录，最终汇总 |

历史不符合当前约束的版本继续归档，不作为严格Triton性能目标。现有三类版本表不因该计划而删减；两版本汇总用于回答方法迁移是否恢复已有能力。

每个试点分为开发与冻结验证两个环节。开发环节允许Codex分析证据并修改workflow／知识库，记录每次指导；冻结验证环节固定workflow、知识、生成模型与预算，CC／DeepSeek可以在既定工具范围内根据结果继续修改候选，Codex不提供临时优化提示。中途需要新方法时转回开发批次，再形成新版本验证，保留此前结果。

验收要求仍为完整正式合同与必要补测通过、全部候选路径严格Triton、相对合格CANN参考超过0.8×。与历史最佳的性能恢复程度单独报告。新生成源码每份SHA默认一次正式完整评测；不得通过复测挑分。

该五算子计划用于能力迁移验证。若其专项历史经验已进入知识库，就属于已有经验复用；不能仅凭这组结果声称对未知算子的泛化。论文实验应额外保留未用于专项方法开发的算子或布局／形状分布，并固定验证集和测试集边界。

## 方法形态：内外两层优化

内层：固定workflow／知识 → CC／DeepSeek生成Triton候选 → KGS／CANN评测 → 性能反馈 → CC／DeepSeek继续修改。

外层：跨运行收集失败轨迹 → Codex分析缺失能力 → 更新workflow／知识 → 在预定任务上验证 → 保留有效方法版本。

外层产物是诊断策略和执行流程；内层产物是算子实现。保持两者身份独立，可以分别衡量算子速度、成功率、模型调用成本和跨算子迁移效果。知识可包含方法及适用条件，不能将整份目标实现伪装成经验替代模型生成。

## 与蒸馏、自改进及RSI的关系

最贴切的现阶段表述是**基于执行反馈的经验提炼与工作流优化**，也可称**诊断策略向工作流与外部记忆的迁移**。

经典模型知识蒸馏通常通过训练学生模型吸收教师知识。本工程当前不更新CC／DeepSeek权重，而是改变其可读取的知识与可执行流程；广义上可描述为经验或策略蒸馏，但论文应明确这种用法，避免与参数蒸馏混淆。

RSI通常指递归自改进：系统修改自身的改进机制，使后续改进能力也提升。改动对象是workflow而非模型权重，并不自动排除系统级RSI；STOP和DGM都涉及程序／agent层面的自修改。单次由Codex更新知识或workflow，也不足以证明递归性。当前更接近有外层诊断器指导的元级优化；若后续系统能够自动提出、验证和保留workflow变体，并证明更新后的优化器能更有效地优化后续任务，才具备更强的递归自改进证据。

## 面向论文的最小验证

保持生成模型、工具可用性、合同与预算一致，比较固定基础workflow与学习后的workflow，测量达标率、正确性、相对CANN性能、调用／token成本，以及临时Codex指导次数。历史最佳源码用于性能恢复对照，不替代方法对照实验。

需要验证的学术问题是：通过提炼少量硬件诊断轨迹得到的可执行方法，能否在冻结后帮助生成模型以更低成本解决更多算子，而不是只记住已有最佳实现。
