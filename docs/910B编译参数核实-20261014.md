# 910B编译参数核实

2026-10-14读取当前`tle_yy`容器已安装的`/usr/local/python3.11.15/lib/python3.11/site-packages/triton/backends/ascend/compiler.py`，其选项类为`NPUOptions`。这是当前安装代码的核实，不是从CUDA文档类推。

| 参数 | 当前代码定义 | 使用依据 |
| --- | --- | --- |
| num_warps | 默认32 | 后端保留此字段；不能按CUDA warp语义解释 |
| num_stages | 910B分支默认2 | 已验证KG profiler候选显式使用1/2，不应笼统说“不支持此参数” |
| multibuffer | 910B分支默认开启 | 与片上缓冲和流水相关，矩阵乘、amin既有测试中有实际尝试 |
| unit_flag | 默认None | 需结合具体backend流水，不能假设任意kernel都获益 |
| sync_solver | 默认None | 同上，使用效果由完整编译及设备计时验证 |
| enable_preload | 默认None | 参数存在不代表BiSheng接受；本机此前有明确编译失败记录 |

此前独立Agent提示词的“num_warps/num_stages不适用”过于绝对。准确表述是：不能移植CUDA调参规则；当前后端存在这些字段，只有本机候选和完整测试可以证明具体配置可用及其性能。为保持已启动批次的知识SHA，当前续跑知识快照原样保留，后续批次更新提示词时纳入本核实结果。

当前logaddexp2原生profiler候选在大半精度输入使用4096元素分块与循环，小半精度输入使用8192分块，并传入不同num_stages；该源码经过36/36完整独立复验两次，约1.267×。这证明这一完整配置能运行，不单独证明参数本身的收益。
