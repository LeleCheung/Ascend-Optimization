# 三类候选与独立 skill 验证

当前原合同及语义口径达标 **26/30**。累计积分的独立数学参考合同另列；本轮版本整理和 skill 验证不增加算子数量。

## 三类版本

| 类别 | 选择与证据 |
| --- | --- |
| 历史最佳（不符合当前约束） | 保存原正式交付选中的源码及已绑定成绩，注明 Ascend C、原生 DMA 或隐式 PyTorch 搬运等原因；不计严格 Triton 成果 |
| 历史最佳（严格 Triton） | 保留拆分前最终交付的候选、逐路径审查、完整结果和补测。实现符合约束与性能达标分别记录 |
| 独立入口验证版（严格 Triton） | 复用已完成的新 CLI／KGS 正式回归，区分既有源码、Codex 修复候选和本轮 skill 实际生成候选 |

“历史最佳”指已有正式交付选中的版本，并非重新穷举全部历史实验后的数学最大值。同源码的历史复测不挑最高分；不同参考、测试合同或计时范围不混合排序。

索引保留语雀原有 **39 项**：1015 的 10 项、1029 新增 20 项、早期 9 项。30 项主线已有冻结的严格 Triton 源码及审查；19 项旧起点不符合现行约束，归档时还纳入原批次正式选中的后续混合候选。早期 `narrow_copy` 的 DMA 混合源码单独保存，其余早期成绩保留历史报告口径，未重新执行现行路径审查与 CANN 回归。不存在证据的类别明确留空，不为每个算子人为生成三份源码。

15 组旧 CANN 结果已与原始请求及源码绑定。请求与源文件仅有 CRLF／LF 差别时分别保存两份字节摘要，并显式记录换行等价。没有绑定原件的历史报告数字不作为新的正式测量。

## 独立模型宿主验证

本轮仅新增 `selu_` 的生成实验，复用固定版本的 FlagGems 起点、合格 CANN 参考、36 项正式合同和双方各42项补测。未向模型提供历史最佳源码；同输入真机 profiling、实际 IR、分类知识和 skill 均保存身份。CC／DeepSeek 负责解释证据、生成候选和处理预检失败；Codex 负责受控调度、工具兼容修复、完整源码审查和正式 KGS 提交。

运行目录、模型调用、失败尝试、生成候选和最终正式结果按不同身份保存。独立入口复测旧源码，与加载 skill 后实际生成新源码，是两个不同结论；新生成候选不会自动覆盖更快的历史交付。

| `selu_` 版本 | 相对 CANN | 完整评测 | 结论 |
| --- | --- | --- | --- |
| 历史严格 Triton 交付 | 0.981745× | 36/36 | 保留原始测量 |
| 同一历史源码经独立入口回归 | 1.039292× | 36/36；双方各42/42补测 | 继续作为当前交付 |
| 独立 skill 实际生成 | 0.210037× | 36/36；双方各42/42补测 | 正确性通过，性能未达标，不替换交付 |

本轮验证了独立 skill 的证据读取、代码生成、错误反馈、审查和完整评测衔接；**没有复现历史最佳性能**。首次正式请求因公共入口冲突在加载阶段失败，第二次为仅入口改名后的新源码，各自只提交一次正式请求，不能把首次失败与后续性能视为可选复测样本。另行增加带偏移切片及周边存储检查，修改前3/9、修复后9/9；入口改名版的设备代码逐字节相同，保留等价绑定。

生成候选的普通输入调用约80–85微秒，对应 CANN 约13微秒；大输入约84／152微秒。现有完整调用结果提示需要补查宿主调度与设备执行，尚不能证明某项开销的独立占比。模型将逐核均值用于全任务 Roofline、将 program 载荷当作指令粒度、将零值解释为采样分辨率的推断未获证实；原诊断保留，审查反馈另存，不把这些推断纳入已验证知识。

控制工具位于 [tools/skill_validation/](../tools/skill_validation/)。`prepare_and_run.py` 用于新的独立试验，`agent_runner.py` 可恢复模型阶段而不重新采集，`agent_tools.py` 暴露上下文和默认最多三份设备预检，`evaluate.py` 在外部逐路径审查后对每份新源码提交一次正式评测；本轮因公共入口兼容修复明确增加第四份预检。这些工具是显式的服务器集成验证器，运行时路径由参数／配置传入，不加入 Python 核心依赖。
